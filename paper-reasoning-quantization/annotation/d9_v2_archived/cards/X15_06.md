## Role Status Handling
`extract_role_status()` is the only source of truth for consensus. An `invalid-format` extraction is a blocking protocol error: the session enters `blocked-escalation` with `escalation_reason = information-gap` produced structurally by the extraction pipeline, the raw review is preserved, and the role is never counted as `agree`. A critical finding with invalid justification follows the same non-rejection principle (per `service-contract/error-management/index.md` §Critical Finding Validation Process): it is downgraded to `high` with the original text preserved, rather than causing an outright review rejection. A missing Core role is `blocked-escalation` with `escalation_reason = risk-threshold-breach`. Core-role presence is checked on every path, not only before simplification. The pre_check gate operates independently of role status extraction but must succeed before any protocol advancement.

**RU:**

## Role Status Handling
`extract_role_status()` является единственным источником истины для консенсуса. Извлечение с ошибкой `invalid-format` представляет собой блокирующую ошибку протокола: сессия переходит в состояние `blocked-escalation` с `escalation_reason = information-gap`, который структурно формируется конвейером извлечения; сырой обзор сохраняется, и роль никогда не учитывается как `agree`. Критическое замечание с недействительным обоснованием следует тому же принципу непринятия (согласно `service-contract/error-management/index.md` §Процесс валидации критических замечаний): оно понижается до `high` с сохранением исходного текста, а не приводит к полному отклонению обзора. Отсутствие роли Core приводит к состоянию `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие роли Core проверяется на каждом пути, а не только перед упрощением. Ворота pre_check функционируют независимо от извлечения статуса роли, но должны успешно пройти перед любым продвижением протокола.
