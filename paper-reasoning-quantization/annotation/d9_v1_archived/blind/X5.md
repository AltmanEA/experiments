## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями принятия решений и не содержит вызовов LLM. Решения по фазе и консенсусу являются детерминированными функциями проверенных выводов ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов из проверенных конфигураций сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо задан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Магических значений по умолчанию нет. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|-------------------------|---------------------|
| temperature | 0.1 | analytical-task reviews |
| top_p | 0.9 | analytical-task reviews |
| frequency_penalty | 0.0 | neutral (установлено явно, никогда не выводится) |

Стандартный белый список централизованно управляется в файле `defaults/policy.yaml`. Для его расширения необходимо подготовить запрос на слияние (PR) с обоснованием. Пересмотр происходит ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, выполните проверку:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никакие несанкционированные инструкции не добавлены за пределами определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, в котором перечислены точные параметры, использованные для каждой активной роли, с возможностью проследить цепочку от конфигурации сценария → резолюции фабрики → фактической инстанциирования агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты пред-фазы), но НЕ изменяет базовый шаблон промта роли. Настройка промта ограничена только акцентированием внимания/внедрением контекста — подмена поведения запрещена.
