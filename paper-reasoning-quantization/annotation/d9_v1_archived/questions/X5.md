## EN-источник

```
  1| ## Moderator
  2| 
  3| The Moderator is the deterministic control plane inside `orchestrator/`. It aggregates role statuses, joins findings by `subject_id`, evaluates consensus through Layer 0, and routes escalation. It performs no free-text interpretation, holds no decision power, and contains no LLM call. Phase and consensus decisions are deterministic functions of validated role outputs; no model participates in control flow or safety verification.
  4| 
  5| ## RoleAgentFactory
  6| 
  7| Centralized factory creating role agent instances from validated scenario config.
  8| 
  9| ### Zero silent defaults policy (ADR-002)
 10| 
 11| Every parameter either specified by caller OR taken from a documented safe value visible in session manifest. No magic defaults. All applied defaults appear in session record under `"configuration_source": "scenario_defaults"` or `"configuration_source": "operator_explicit"`.

 14| |-----------|---------|-------|

 16| | top_p | 0.9 | analytical-task reviews |
 17| | frequency_penalty | 0.0 | neutral (explicitly set, never inferred) |
 18| 
 19| Default whitelist managed centrally in `defaults/policy.yaml`. Expansion requires PR with justification. Reviewed quarterly.
 20| 
 21| ### Contract validation hook
 22| 
 23| After creation but before enqueue, verify:
 24| 
 25| - Role identifier matches known role from `protocol-core/index.md`
 26| - Prompt template contains required sections (perspective, responsibilities, output structure reminder)
 27| - No unauthorized instructions appended beyond role definition and scenario context
 28| 
 29| ### Session manifest traceability
 30| 
 31| Each session record includes `"role_agent_config"` section listing exact parameters used for each active role, traceable back to scenario config → factory resolution → actual agent instantiation.
 32|

 34| 
 35| Factory injects scenario-specific context (task scope, scenario name, pre-phase results) but does NOT modify the role's base prompt template. Prompt customization scoped to emphasis/context injection only — behavioral substitution prohibited.
```

## Вопрос 1 — кандидаты. Ответ: одна строка из цифр, по одной на кандидата
(порядок A1, A2, …): `0` — не дефект; `1`/`2`/`3` — дефект, minor/major/critical.
Например, для 4 кандидатов: `0203` (A2 — major, A4 — critical, остальные — не дефекты).

- **A1** [термин] EN:3 — цитата: `Phase` — глоссарий: требуется RU-эквивалент «Фаза» — не найден ⚠ пограничный
- **A2** [термин] RU:5 — цитата: `Role Agent` — глоссарий: требуется RU-эквивалент «Ролевой агент» — не найден ⚠ пограничный
- **A3** [добавление] RU:3 — цитата: `вывод` — RU-слово «вывод» — эквивалент термина, которого нет в EN этого прогона ⚠ пограничный
- **A4** [добавление] RU:11 — цитата: `замечания` — RU-слово «замечания» — эквивалент термина, которого нет в EN этого прогона ⚠ пограничный
- **A5** [смысл] RU:11 — цитата: `безопасного замечания` — The term 'value' is mistranslated as 'замечание' (remark/note) instead of 'значение'. ⚠ пограничный
- **A6** [смысл] RU:11 — цитата: `применённые замечания по умолчанию` — The term 'defaults' (default values) is mistranslated as 'замечания по умолчанию' instead of 'значения по умолчанию'. ⚠ пограничный
- **A7** [формулировка] RU:31 — цитата: `фактической инстанциирования` — Grammatical gender mismatch: the adjective 'фактической' (feminine) does not agree with the noun 'инстанциирования' (neuter). ⚠ пограничный

## Вопрос 2 — другие фактические искажения (числа, подмена терминов,
потеря/добавление смысла), которых нет в списке кандидатов?
Ответ — одно число: `0` — нет; `1`/`2`/`3` — нашли искажение
minor/major/critical. Несколько — через запятую (например `3,2`).
