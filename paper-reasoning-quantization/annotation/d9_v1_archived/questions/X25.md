# Карточка X25 — прогон из фикстуры S6 (повтор 2)

Строки пронумерованы (`N| текст`); в вопросах ссылки — на эти номера.

## EN-источник

```
  1| ## Moderator
  2| 
  3| The Moderator is the deterministic control plane inside `orchestrator/`. It aggregates role statuses, joins findings by `subject_id`, evaluates consensus through Layer 0, and routes escalation. It performs no free-text interpretation, holds no decision power, and contains no LLM call. Phase and consensus decisions are deterministic functions of validated role outputs; no model participates in control flow or safety verification.
  4| 
  5| ## RoleAgentFactory
  6| 
  7| Centralized factory creating role agent instances from validated scenario config.
  8| 
  9| ### Zero silent defaults policy (ADR-002)
 10| 
 11| Every parameter either specified by caller OR taken from a documented safe value visible in session manifest. No magic defaults. All applied defaults appear in session record under `"configuration_source": "scenario_defaults"` or `"configuration_source": "operator_explicit"`.
 12| 
 13| | Parameter | Default | Scope |
 14| |-----------|---------|-------|
 15| | temperature | 0.1 | analytical-task reviews |
 16| | top_p | 0.9 | analytical-task reviews |
 17| | frequency_penalty | 0.0 | neutral (explicitly set, never inferred) |
 18| 
 19| Default whitelist managed centrally in `defaults/policy.yaml`. Expansion requires PR with justification. Reviewed quarterly.
 20| 
 21| ### Contract validation hook
 22| 
 23| After creation but before enqueue, verify:
 24| 
 25| - Role identifier matches known role from `protocol-core/index.md`
 26| - Prompt template contains required sections (perspective, responsibilities, output structure reminder)
 27| - No unauthorized instructions appended beyond role definition and scenario context
 28| 
 29| ### Session manifest traceability
 30| 
 31| Each session record includes `"role_agent_config"` section listing exact parameters used for each active role, traceable back to scenario config → factory resolution → actual agent instantiation.
 32| 
 33| ### No prompt modification rule
 34| 
 35| Factory injects scenario-specific context (task scope, scenario name, pre-phase results) but does NOT modify the role's base prompt template. Prompt customization scoped to emphasis/context injection only — behavioral substitution prohibited.
```

## RU-вывод

```
  1| ## Moderator
  2| 
  3| Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы Ролей, объединяет выводы по `subject_id`, оценивает Консенсус через Layer 0 и маршрутизирует Эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по Фаза и Консенсус являются детерминированными функциями проверенных выходов Ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.
  4| 
  5| ## RoleAgentFactory
  6| 
  7| Централизованная фабрика, создающая экземпляры ролевого агента из валидированной конфигурации сценария.
  8| 
  9| ### Zero silent defaults policy (ADR-002)
 10| 
 11| Каждый параметр либо указывается вызывающей стороной, либо берётся из задокументированного безопасного замечания, отображаемого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.
 12| 
 13| | Параметр | По умолчанию | Область |
 14| |-----------|---------|-------|
 15| | temperature | 0.1 | аналитическая-задача: обзоры |
 16| | top_p | 0.9 | аналитическая-задача: обзоры |
 17| | frequency_penalty | 0.0 | нейтральный (установлен явно, никогда не выводится) |
 18| 
 19| Белый список по умолчанию управляется централизованно в `defaults/policy.yaml`. Для его расширения требуется PR с обоснованием. Пересматривается ежеквартально.
 20| 
 21| ### Contract validation hook
 22| 
 23| После создания, но перед добавлением в очередь, проверьте:
 24| 
 25| - Идентификатор роли соответствует известной роли из `protocol-core/index.md`
 26| - Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
 27| - Отсутствуют несанкционированные инструкции, добавленные за пределы определения роли и контекста сценария
 28| 
 29| ### Session manifest traceability
 30| 
 31| Каждая запись сессии включает раздел `"role_agent_config"`, перечисляющий точные параметры, использованные для каждой активной роли, которые можно отследить до конфигурации сценария → резолюции фабрики → фактической инстанциирования агента.
 32| 
 33| ### No prompt modification rule
 34| 
 35| Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты предфазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничена только акцентом/внедрением контекста — поведенческая подмена запрещена.
```
