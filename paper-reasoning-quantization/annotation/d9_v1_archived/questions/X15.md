# Карточка X15 — прогон из фикстуры S5 (повтор 1)

Строки пронумерованы (`N| текст`); в вопросах ссылки — на эти номера.

## EN-источник

```
  1| ## Deterministic Control Plane
  2| 
  3| Moderator control flow and every phase, consensus, and escalation decision are deterministic functions of validated role outputs. No LLM participates in control flow or safety verification. The Moderator may read free text only for display; it never interprets it to make a decision. Scenario loading falls back to `default-council-session` (see `scenario/default-council-session.yaml`) when no explicit `scenario_id` is provided in the session manifest.
  4| 
  5| ## Phase State Machine
  6| 
  7| States: `1` task submission, `2` individual review, `3` discussion, `4` consensus check, `5` resolution, plus `awaiting-operator`, `resolved`, `failed`.
  8| 
  9| | From | To | Guard |
 10| |------|----|-------|
 11| | 1 | 2 | Task validated; scenario loaded; locked_roles resolved against operator_approval per `service-contract/index.md` §Session Manifest |
 12| | 2 | 3 | Every active role has `RoleStatus` with `extraction = parsed` |
 13| | 2 | awaiting-operator | Any `invalid-format` status or missing Core role |
 14| | 3 | 4 | Round limit reached, or no new `blocked-in-scope` |
 15| | 3 | 3 | At least one `blocked-in-scope` and targeted-round budget remains |
 16| | 4 | 5 | Per protocol-core §Outcome-to-Transition table: `consensus` or `conditional` → Phase 5 |
 17| | 4 | 3 | Per protocol-core §Outcome-to-Transition table: `no-consensus` with remaining budget → re-enter Phase 3; decrements `no_consensus_budget`. |
 18| | 4 | awaiting-operator | Per protocol-core §Outcome-to-Transition table: `blocked-escalation`; OR `no-consensus` with exhausted budget (`no_consensus_budget` reaches zero → `blocked-escalation` with `escalation_reason = information-gap`) → `awaiting-operator` |
 19| | 5 | resolved | Final artifact persisted; manifest updated last |
 20| | awaiting-operator | `resume_phase` | Operator resolution bound to `escalation_id` |
 21| | N → N+1 | Mandatory at phase boundaries per layer definition. Fails fast on high/critical Documenter finding (percheck failed). Precheck unavailable → override permitted via council.override_precheck (precheck.overridden event). Override recorded in manifest as pre_check_override; permits exactly one transition after which another pass or new override required. |
 22| | any | failed | Unrecoverable IO or protocol violation |
 23| 
 24| Only `orchestrator/` advances a phase. The operator never edits phase state directly; resolution arrives through the operator surface. The `SUBJ-007` quick-review upgrade hook is reserved but not implemented at MVP.
 25| 
 26| ## Role Status Handling
 27| 
 28| `extract_role_status()` is the only source of truth for consensus. An `invalid-format` extraction is a blocking protocol error: the session enters `blocked-escalation` with `escalation_reason = information-gap` produced structurally by the extraction pipeline, the raw review is preserved, and the role is never counted as `agree`. A critical finding with invalid justification follows the same non-rejection principle (per `service-contract/error-management/index.md` §Critical Finding Validation Process): it is downgraded to `high` with the original text preserved, rather than causing an outright review rejection. A missing Core role is `blocked-escalation` with `escalation_reason = risk-threshold-breach`. Core-role presence is checked on every path, not only before simplification. The pre_check gate operates independently of role status extraction but must succeed before any protocol advancement.
```

## RU-вывод

```
  1| ## Deterministic Control Plane
  2| 
  3| Поток управления модератора и каждый этап, консенсус и решение об эскалации являются детерминированными функциями проверенных выходов ролей. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка сценария по умолчанию использует `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте сессии не указан явный `scenario_id`.
  4| 
  5| ## Phase State Machine
  6| 
  7| Состояния: `1` отправка задачи, `2` индивидуальный обзор, `3` обсуждение, `4` проверка консенсуса, `5` разрешение, а также `awaiting-operator`, `resolved`, `failed`.
  8| 
  9| | От | До | Охрана |
 10| |------|----|-------|
 11| | 1 | 2 | Задача проверена; сценарий загружен; locked_roles разрешены в соответствии с operator_approval согласно `service-contract/index.md` §Манифест сессии |
 12| | 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
 13| | 2 | awaiting-operator | Любой статус `invalid-format` или отсутствие роли Core |
 14| | 3 | 4 | Достигнут лимит раундов, или нет новых `blocked-in-scope` |
 15| | 3 | 3 | По крайней мере один `blocked-in-scope` и остаётся бюджет целевого раунда |
 16| | 4 | 5 | Согласно таблице протокола-core §Outcome-to-Transition: `consensus` или `conditional` → Фаза 5 |
 17| | 4 | 3 | Согласно таблице протокола-core §Outcome-to-Transition: `no-consensus` при наличии оставшегося бюджета → повторный вход в Фазу 3; уменьшает `no_consensus_budget`. |
 18| | 4 | awaiting-operator | Согласно таблице протокола-core §Outcome-to-Transition: `blocked-escalation`; ИЛИ `no-consensus` при исчерпанном бюджете (`no_consensus_budget` достигает нуля → `blocked-escalation` с `escalation_reason = information-gap`) → `awaiting-operator` |
 19| | 5 | resolved | Финальный артефакт сохранён; манифест обновлён последним |
 20| | awaiting-operator | `resume_phase` | Разрешение оператора связано с `escalation_id` |
 21| | N → N+1 | Обязательно на границах фаз согласно определению слоя. Быстрый отказ при обнаружении высокого/критического документа (проверка не пройдена). Если precheck недоступен → разрешение на обход через council.override_precheck (событие precheck.overridden). Обход записывается в манифест как pre_check_override; разрешает ровно один переход, после чего требуется ещё один проход или новый обход. |
 22| | any | failed | Невосстановимая ошибка ввода-вывода или нарушение протокола |
 23| 
 24| Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; разрешение приходит через интерфейс оператора. Хук быстрого обновления `SUBJ-007` зарезервирован, но не реализован на этапе MVP.
 25| 
 26| ## Role Status Handling
 27| 
 28| `extract_role_status()` является единственным источником истины для консенсуса. Извлечение с ошибкой `invalid-format` представляет собой блокирующую ошибку протокола: сессия переходит в состояние `blocked-escalation` с `escalation_reason = information-gap`, который структурно формируется конвейером извлечения; сырой обзор сохраняется, и роль никогда не учитывается как `agree`. Критическое замечание с недействительным обоснованием следует тому же принципу непринятия (согласно `service-contract/error-management/index.md` §Процесс валидации критических замечаний): оно понижается до `high` с сохранением исходного текста, а не приводит к полному отклонению обзора. Отсутствие роли Core приводит к состоянию `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие роли Core проверяется на каждом пути, а не только перед упрощением. Ворота pre_check функционируют независимо от извлечения статуса роли, но должны успешно пройти перед любым продвижением протокола.
```

## Вопрос 1 — кандидаты. Ответ: одна строка из цифр, по одной на кандидата
(порядок A1, A2, …): `0` — не дефект; `1`/`2`/`3` — дефект, minor/major/critical.
Например, для 4 кандидатов: `0203` (A2 — major, A4 — critical, остальные — не дефекты).

- **A1** [формат] RU:5 — цитата: `Phase State Machine` — Header not translated. ⚠ пограничный
- **A2** [формат] RU:26 — цитата: `Role Status Handling` — Header not translated. ⚠ пограничный
- **A3** [формат] RU:21 — цитата: `council.override_precheck` — Code token `council.override_precheck` is not backticked as required. ⚠ пограничный
- **A4** [формат] RU:11 — цитата: `locked_roles` — Code token `locked_roles` is not backticked as required. ⚠ пограничный
- **A5** [формат] RU:11 — цитата: `operator_approval` — Code token `operator_approval` is not backticked as required. ⚠ пограничный
- **A6** [формат] RU:21 — цитата: `pre_check_override` — Code token `pre_check_override` is not backticked as required. ⚠ пограничный
- **A7** [термин] EN:21 — цитата: `Documenter` — глоссарий: требуется RU-эквивалент «Документатор» — не найден ⚠ пограничный
- **A8** [термин] EN:7 — цитата: `Resolution` — глоссарий: требуется RU-эквивалент «Резолюция» — не найден ⚠ пограничный
- **A9** [термин] RU:7 — цитата: ``5` разрешение` — Used "разрешение" where the required term is "Резолюция" (Resolution). ⚠ пограничный
