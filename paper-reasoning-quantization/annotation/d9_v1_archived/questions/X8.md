# Карточка X8 — прогон из фикстуры S5 (повтор 1)

Строки пронумерованы (`N| текст`); в вопросах ссылки — на эти номера.

## EN-источник

```
  1| ## Deterministic Control Plane
  2| 
  3| Moderator control flow and every phase, consensus, and escalation decision are deterministic functions of validated role outputs. No LLM participates in control flow or safety verification. The Moderator may read free text only for display; it never interprets it to make a decision. Scenario loading falls back to `default-council-session` (see `scenario/default-council-session.yaml`) when no explicit `scenario_id` is provided in the session manifest.
  4| 
  5| ## Phase State Machine
  6| 
  7| States: `1` task submission, `2` individual review, `3` discussion, `4` consensus check, `5` resolution, plus `awaiting-operator`, `resolved`, `failed`.
  8| 
  9| | From | To | Guard |
 10| |------|----|-------|
 11| | 1 | 2 | Task validated; scenario loaded; locked_roles resolved against operator_approval per `service-contract/index.md` §Session Manifest |
 12| | 2 | 3 | Every active role has `RoleStatus` with `extraction = parsed` |
 13| | 2 | awaiting-operator | Any `invalid-format` status or missing Core role |
 14| | 3 | 4 | Round limit reached, or no new `blocked-in-scope` |
 15| | 3 | 3 | At least one `blocked-in-scope` and targeted-round budget remains |
 16| | 4 | 5 | Per protocol-core §Outcome-to-Transition table: `consensus` or `conditional` → Phase 5 |
 17| | 4 | 3 | Per protocol-core §Outcome-to-Transition table: `no-consensus` with remaining budget → re-enter Phase 3; decrements `no_consensus_budget`. |
 18| | 4 | awaiting-operator | Per protocol-core §Outcome-to-Transition table: `blocked-escalation`; OR `no-consensus` with exhausted budget (`no_consensus_budget` reaches zero → `blocked-escalation` with `escalation_reason = information-gap`) → `awaiting-operator` |
 19| | 5 | resolved | Final artifact persisted; manifest updated last |
 20| | awaiting-operator | `resume_phase` | Operator resolution bound to `escalation_id` |
 21| | N → N+1 | Mandatory at phase boundaries per layer definition. Fails fast on high/critical Documenter finding (percheck failed). Precheck unavailable → override permitted via council.override_precheck (precheck.overridden event). Override recorded in manifest as pre_check_override; permits exactly one transition after which another pass or new override required. |
 22| | any | failed | Unrecoverable IO or protocol violation |
 23| 
 24| Only `orchestrator/` advances a phase. The operator never edits phase state directly; resolution arrives through the operator surface. The `SUBJ-007` quick-review upgrade hook is reserved but not implemented at MVP.
 25| 
 26| ## Role Status Handling
 27| 
 28| `extract_role_status()` is the only source of truth for consensus. An `invalid-format` extraction is a blocking protocol error: the session enters `blocked-escalation` with `escalation_reason = information-gap` produced structurally by the extraction pipeline, the raw review is preserved, and the role is never counted as `agree`. A critical finding with invalid justification follows the same non-rejection principle (per `service-contract/error-management/index.md` §Critical Finding Validation Process): it is downgraded to `high` with the original text preserved, rather than causing an outright review rejection. A missing Core role is `blocked-escalation` with `escalation_reason = risk-threshold-breach`. Core-role presence is checked on every path, not only before simplification. The pre_check gate operates independently of role status extraction but must succeed before any protocol advancement.
```

## RU-вывод

```
  1| ## Deterministic Control Plane
  2| 
  3| Поток управления Модератора и каждое решение по Фазе, Консенсусу и Эскалации являются детерминированными функциями валидированных выходов Роль. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка Сценария возвращается к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте Сессии не указан явный `scenario_id`.
  4| 
  5| ## Phase State Machine
  6| 
  7| Состояния: `1` подача задачи, `2` персональная проверка, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `awaiting-operator`, `resolved`, `failed`.
  8| 
  9| | От | К | Условие |

 18| | 4 | awaiting-operator | Согласно таблице §Outcome-to-Transition в protocol-core: `blocked-Эскалация`; ИЛИ `no-Консенсус` при исчерпанном бюджете (`no_consensus_budget` достигает нуля → `blocked-Эскалация` с `escalation_reason = information-gap`) → `awaiting-operator` |
 19| | 5 | resolved | Финальный Артефакт сохранён; манифест обновлён в последнюю очередь |

Precheck недоступен → override разрешён через council.override_precheck (precheck.overridden event).  24| Только `orchestrator/` переходит к следующей фазе. Оператор никогда не изменяет состояние фазы напрямую; Резолюция поступает через интерфейс оператора. Хук обновления `SUBJ-007` для быстрого обзора зарезервирован, но не реализован на этапе MVP.
 25| 
 26| ## Role Status Handling
 27| 
 28| `extract_role_status()` является единственным источником истины для Консенсуса. Извлечение с `invalid-format` представляет собой блокирующую ошибку протокола: Сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, формируемым конвейером извлечения, сырой отзыв сохраняется, а Роль никогда не засчитывается как `Согласие`. Критический Вывод с некорректным обоснованием подчиняется тому же принципу отсутствия отклонения (согласно `service-contract/error-management/index.md` §Процесс проверки критического Вывода): он понижается до `high` с сохранением исходного текста, вместо того чтобы вызывать прямой отказ в рассмотрении. Отсутствие Роль Core трактуется как `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Проверка наличия Роль Core выполняется на каждом пути, а не только перед упрощением. Ворота pre_check функционируют независимо от извлечения Статус роли, но должны успешно пройти перед любым продвижением протокола.
```

## Вопрос 1 — кандидаты. Ответ: одна строка из цифр, по одной на кандидата
(порядок A1, A2, …): `0` — не дефект; `1`/`2`/`3` — дефект, minor/major/critical.
Например, для 4 кандидатов: `0203` (A2 — major, A4 — critical, остальные — не дефекты).

- **A1** [формат] RU:18 — цитата: ``blocked-Эскалация`` — Code token altered: original `blocked-escalation` changed to Russian text. ⚠ пограничный
- **A2** [формат] RU:17 — цитата: ``no-Консенсус`` — Code token altered: original `no-consensus` changed to Russian text. ⚠ пограничный
- **A3** [формат] EN:28 — цитата: `agree` — токен `agree` из EN не найден в RU дословно ⚠ пограничный
- **A4** [формат] RU:17 — цитата: `consensus` — токен `consensus` из EN не найден в RU дословно ⚠ пограничный
- **A5** [формат] RU:17 — цитата: `no-consensus` — токен `no-consensus` из EN не найден в RU дословно ⚠ пограничный
- **A6** [смысл] RU:18 — цитата: `blocked-Эскалация` — Backticked code token 'blocked-escalation' was partially translated; must be byte-identical. ⚠ пограничный
- **A7** [смысл] RU:17 — цитата: `no-Консенсус` — Backticked code token 'no-consensus' was partially translated; must be byte-identical. ⚠ пограничный
- **A8** [формулировка] RU:11 — цитата: `§Сессия Manifest` — Awkward phrasing and incorrect word order for 'Session Manifest'. ⚠ пограничный
- **A9** [формулировка] RU:21 — цитата: `Вывод Документатор` — Incorrect case/inflection for glossary term 'Документатор'. ⚠ пограничный
- **A10** [смысл] RU:3 — цитата: `Консенсус` — Backticked code token 'consensus' was translated; must be byte-identical. ⚠ пограничный
