Обновлено: 2026-11-16. Файл самодостаточен: новая сессия может провести весь опрос, прочитав
только его. Цель — закрыть B1 из `PLAN-CLOSEOUT.md` (ручная D9-разметка, требование `PLAN.md`

## 1. Что размечено и чем это является

- Выборка: 30 прогонов из 483 Council-прогонов (23 условия × 21), seed 20261116,
  стратифицирована по условиям (все 22 условия ≥1 прогоном; raw-C2 исключён, взят C2_clean).
  48 (10 %) не брали сознательно — §9.4 раскрывает сниженную долю (≈6 %).
- Ключ X→условие: `annotation/d9/manifest_key.json`. **Не открывать и не печатать до
  заморозки ответов.** Аннотатор видит только X-номера.
- Карточки: `annotation/d9/v4/cards/X<k>_<i>.md`, 150 шт. (5 на прогон), сгенерированы
  `metrics/d9_para.py` (детерминированно). Машина-ключ карточек: `annotation/d9/v4/items.json`.

## 2. Методика (итоговая; v1–v3 отвергнуты, их ответы аннулированы)

Почему не раньше: v1 (кандидаты+свободный ввод) — тяжело и наводяще; v2 (вопрос «есть ли
искажения в абзаце?») — недостоверно: человек вынужден выдумывать объект ответа. Итог:

**Карточка = абзац EN + выровненный абзац RU + ОДИН конкретный вопрос про фрагмент внутри
этого абзаца. Ответ — одна цифра: `0` не искажение; `1` minor; `2` major; `3` critical.**

Типы вопросов (см. `metrics/d9_para.py`): `code` (токен в бэктиках байт-в-байт), `num`
(число/идентификатор сохранён), `term` (глоссарийный эквивалент), `judge` (фрагмент, в
котором усомнился LLM-судья; цитаты EN и RU друг под другом, вердикт судьи не показывается
как ответ — только как повод). Открытых вопросов НЕТ.

Контроль качества разметки: вперемешку идут control-карточки с известным заранее ответом —
`neg` (фрагменты совпадают, правильный ответ 0; сейчас 103) и `pos` (заведомое искажение —
порченный токен/потерянное число/пропущенный термин; 23). Остальные 24 карточки — основной
сигнал: вопросы `judge` (фрагменты, в которых усомнились судьи; правильного ответа заранее
не известно). Доля ошибок на neg-контроле >15 %
= разметку не принимать, перезапуск с инструкцией. κ считается **только по неконтрольным**
вопросам; по pos-контролю репортится recall аннотатора.

Слепота: карточки генерируются скриптом и передаются человеку 1-в-1 (агент — ретранслятор,
без своих комментариев и подсказок). Перед вскрытием ключа ответы замораживаются по sha256.

## 3. Протокол проведения (для агента-интервьюера)

> ### ⊗ АБСОЛЮТНЫЙ ЗАПРЕТ (нарушение обесценивает весь B1)
>
> Агент — **только ретранслятор карточек и секретарь ответов**. Агент **ЗАПРЕЩАЕТСЯ**:
> - отвечать на карточки сам (целиком, частично, «предварительно», «для примера», «для
>   демонстрации формата» — любые формулировки не меняют сути);
> - интерпретировать EN/RU, сравнивать их, объяснять, почему ответ 0 или 2;
> - предполагать, подсказывать, предлагать варианты ответа, комментировать ответы человека;
> - записывать в `d9_answer.py` что-либо, кроме буквальных цифр из сообщения человека.
>
> Почему: измеряется согласие **человека** с LLM-судьями. Ответы агента — это вторые LLM-судьи,
> κ «сам с собой» — методологическое нуле-значение, публикация с такими данными — подлог.
> Если человек молчит — агент ждёт. Никаких «пока начну с X1».
>
> Единственный легитимный контент от агента: текст карточек дословно + строка-шаблон
> «Ответ: цифры через пробел, например `0 2 0 …`» + записи `d9_answer.py` с цифрами человека.

Протокол одного прогона (петля обязательна, шаг за шагом):

1. Прочитать `annotation/d9/METHOD-v4.md` (этот файл). Проверить `python3 metrics/d9_answer.py
   --status` — какие карточки ещё не отвечены.
2. Для каждого прогона X (по порядку X1…X30): отправить ОДНО сообщение со всеми его
   карточками (1–5): заголовок `X<k>#<i>`, блоки EN и RU дословно из файла карточки, вопрос,
   строку с вариантами ответа. Формат ответа от человека: цифры по числу карточек
   (`0 0 2 0 1`). Карточку печатать дословно, ничего не добавлять от себя, не комментировать
   предыдущие ответы.
3. **СТОП. Закончить ход и ждать сообщения человека.** Не делать никаких tool-вызовов
   «пока жду». Не отвечать себе.
4. Получив сообщение с цифрами от человека — разобрать их строго позиционно (i-я цифра =
   i-я карточка сообщения; цифры из другого содержания не извлекать; если цифр меньше, чем
   карточек — переспросить недостающие, не дополнять самому) и записать:
   `python3 metrics/d9_answer.py --batch "X1#1=0 X1#2=0 X1#3=2 ..."`
   (или по одной: `d9_answer.py X1#1 0`). Все ответы — только через этот скрипт (аудит-трейл
   `v4/answers.csv` + `v4/answers.log`).
5. Прогон закрыт, когда у X отвечены все карточки (`--status`). Перейти к следующему X
   (шаг 2). Полный опрос = 150 карточек, ≈2–2.5 ч человеческого времени.
6. После последних ответов:
   - `python3 metrics/d9_answer.py --freeze` (sha256 ответов в `v4/answers_frozen.sha256`);
   - ТОЛЬКО теперь вскрывать `manifest_key.json`;
   - посчитать κ (см. §5), записать SUMMARY §7 «Калибровка по человеку» + переформулировать
     §9.4; обновить `STATUS.md` / `PLAN-CLOSEOUT.md` (B1 закрыт).

## 4. Критерии для аннотатора (дать прочесть до старта, 1 страница)

Дефект D9 = фактическое искажение: изменённое число/идентификатор, подменённый глоссарийный
термин, потеря или добавление смысла, порча `кода` (токен в бэктиках обязан совпадать
посимвольно), лишние строки (в т. ч. английские «Let's…», «Wait…»). НЕ дефект: склонение/падеж
правильного термина, порядок слов, стилевые и синонимические варианты вне глоссария.
Severity: 3 — изменённое число, испорченный `код`, потеря обязательного поля, утечка
рассуждений; 2 — подменённый термин, потеря целого утверждения; 1 — косметика формата.
Если фрагмент в абзаце не читается полностью (обрыв) — отвечать по видимому, пограничные
отмечать цифрой с `?` (например `2?`) — они пересматриваются второй оценкой (PLAN §6.1).

## 5. Обработка (после freeze)

`metrics/d9_agreement.py` — базовый скрипт (сверка полос/весов с P-003c), но он писался под
v1 (cand/free). Для v4 нужна версия: человеческий ответ по карточке severity 1/2/3 → вес
2/10/25 (тот же MQM-скор `judge.py`: 100 − Σ, пол); по прогону — сумма по карточкам
(контрольные карточки в сумму НЕ входят) → полоса A–E из `judge_agreement.py`; κ weighted
человек vs средний судья (файлы `judge/absolute/<cond>/<fix>/<rep>.<judge>.json`), плюс
двоичный κ «≥1 critical» и recall судьи на человеческих critical; bootstrap 20 000,
seed 20261116; отдельно: accuracy на neg-контроле, recall на pos-контроле. Выход —
`results/d9_agreement.md/.csv`. Это доработать до начала подсчёта (A-задача, 1 ч).
