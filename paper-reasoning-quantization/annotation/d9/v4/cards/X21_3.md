# X21#3 — абзац 3

**EN:**

> ### EscalationRecord
> | Field | Type | Required | Rule |
> |-------|------|----------|------|
> | `escalation_id` | string | yes | Identifier format |
> | `session_id` | string | yes | |
> | `raised_by_role` | string | yes | |
> | `reason` | enum | yes | `escalation_reason` |
> | `severity` | enum | yes | |
> | `blocker` | string | yes | 1–2000 chars |
> | `positions` | object[] | yes | `{role_id, stance, summary}` per side |
> | `operator_request` | string | yes | One concrete decision or missing input |
> | `fallback_strategy` | string | yes | What happens if the operator does not answer |
> | `timeout_at` | timestamp \| null | yes | `null` when no deadline is set |
> | `resolution` | object | yes | `{state: pending\|accepted\|rejected\|superseded\|expired, note, operator_id, resolved_at}` |
> | `resume_phase` | integer | yes | Exact phase to resume |

**RU:**

> ### EscalationRecord
> | Поле | Тип | Обязательно | Правило |
> |-------|------|----------|------|
> | `id_эскалации` | string | yes | Формат идентификатора |
> | `id_сессии` | string | yes | |
> | `поднято_ролью` | string | yes | |
> | `reason` | enum | yes | `причина_эскалации` |
> | `уровень_серьёзности` | enum | yes | |
> | `blocker` | string | yes | 1–2000 символов |
> | `positions` | object[] | yes | `{id_роли, позиция, краткое_описание}` для каждой стороны |
> | `operator_request` | string | yes | Одно конкретное решение или отсутствующие данные |
> | `fallback_strategy` | string | yes | Что происходит, если оператор не отвечает |
> | `timeout_at` | timestamp \| null | yes | `null`, если срок не установлен |
> | `резолюция` | object | yes | `{state: pending\|accepted\|rejected\|superseded\|expired, note, operator_id, resolved_at}` |
> | `фаза_возобновления` | integer | yes | Точная фаза для возобновления |

**Вопрос.** Числа/идентификаторы должны совпадать. EN `1` → RU `1`. Это искажение?

Ответ одной цифрой: 0 = не искажение; 1 = minor; 2 = major; 3 = critical.
