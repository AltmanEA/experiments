## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) как синхронный вызов `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия:** все документы манифеста, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией состояния новой фазы в Слое 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при результате `pass`.
- **Передача результата в Слой 1:** поверхность записывает результат (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Отсутствие `high`/`critical` выводов для целевой области | `pass` | Перейти к переходу |
| Наличие любого `high` или `critical` вывода | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (сетевая ошибка, таймаут, сервис не работает) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать операцию бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- В записи обхода указывается `reason` (произвольный текст, поясняющий, почему шлюз был обойден).
- Информация об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход позволяет ровно один последующий переход фазы без новой проверки. После этого перехода для следующего рубежа требуется новый проход или новый обход.
- Обход никогда не позволяет обойти требования присутствия роли Core, правила консенсуса или шлюзы целостности эскалации.
