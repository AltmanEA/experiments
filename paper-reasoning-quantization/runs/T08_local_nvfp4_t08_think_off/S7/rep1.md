## `pre_check` Gate

### Scope and Enforcement Point

Ворота `pre_check` представляют собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Она выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова функции `audit(pre_check=true)` модуля **Документатор** и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия цели:** все манифестные документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в слое 1.
- **Переходы через шлюзы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при решении `pass`.
- **Передача решения слою 1:** поверхность записывает результат решения (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении либо генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границы и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|---------|---------|----------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; создать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Заблокировать переход; создать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор НЕ ДОЛЖЕН блокировать процесс бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Переопределение записывает `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова переопределения.
- Переопределение допускает ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует другого прохода или нового переопределения.
- Переопределение никогда не обходит правила присутствия роли Core, правила консенсуса или шлюзы целостности эскалации.
