## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется в слое 2 (поверхности оператора) как синхронный вызов метода `audit(pre_check=true)` компонента **Документатор** и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все манифестные документы, относящиеся к текущей сессии (определяются через `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией состояния новой фазы в Слое 1.
- **Переходы с проверкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только в случае, если вердикт имеет значение `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при перезаписи или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует её.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис не работает) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/нечитаем | `fail` | Заблокировать переход (отказ в закрытом режиме согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор НЕ ДОЛЖЕН блокировать бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Записи об обходе содержат `reason` (свободный текст, объясняющий причину обхода проверки).
- Запись об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход допускает ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует другого прохождения или нового обхода.
- Обход никогда не обходит наличие ролей ядра, правила консенсуса или целостные шлюзы эскалации.
