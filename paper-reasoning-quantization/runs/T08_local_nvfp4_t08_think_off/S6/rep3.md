## Moderator

Модератор — это детерминированная плоскость управления внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через Уровень 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения относительно фазы и консенсуса являются детерминированными функциями проверенных выводов ролей; никакая модель не участвует в управлении потоком или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|---------|-------|
| температура | 0.1 | анализ-задачи, отзывы |
| top_p | 0.9 | анализ-задачи, отзывы |
| frequency_penalty | 0.0 | нейтральная (явно задача, никогда не выводится) |

Стандартный белый список (whitelist) управляется централизованно в файле `defaults/policy.yaml`. Для его изменения требуется создание pull-запроса (PR) с обоснованием. Пересмотр осуществляется ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, выполните проверку:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никаких несанкционированных инструкций, добавленных за пределами определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии содержит раздел `"role_agent_config"`, перечисляющий точные параметры, использованные для каждой активной роли, которые можно отследить до конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты пред-фазы), но НЕ изменяет базовый шаблон подсказки Роль. Настройка подсказки ограничена только акцентом/внедрением контекста — подмена поведения запрещена.
