## Deterministic Control Plane

**Модератор** контролирует поток выполнения, а каждая **фаза**, **консенсус** и решение об **эскалации** являются детерминированными функциями проверенных выходов **ролей**. Ни одна LLM не участвует в управлении потоком или проверке безопасности. **Модератор** может читать произвольный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка **сценария** выполняется с использованием `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте **сессии** не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` отправка задачи, `2` индивидуальный обзор, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, а также `awaiting-operator`, `resolved`, `failed`.

| От | До | Ограничение |
|------|----|-------|
| 1 | 2 | Задача проверена; сценарий загружен; locked_roles разрешены в соответствии с operator_approval согласно `service-contract/index.md` §Сессия Манифест |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | ожидание-оператора | Любой статус `invalid-format` или отсутствует Core роль |
| 3 | 4 | Достигнут лимит раундов, или нет новых `blocked-in-scope` |
| 3 | 3 | Есть как минимум один `blocked-in-scope` и остаётся бюджет целевого раунда |
| 4 | 5 | Согласно протоколу-ядро §Таблица Исход-в-Переход: `consensus` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно протоколу-ядро §Таблица Исход-в-Переход: `no-consensus` при наличии оставшегося бюджета → повторное входение в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | ожидание-оператора | Согласно протоколу-ядро §Таблица Исход-в-Переход: `blocked-escalation`; ИЛИ `no-consensus` при исчерпанном бюджете (`no_consensus_budget` достигает нуля → `blocked-escalation` с `escalation_reason = information-gap`) → `ожидание-оператора` |
| 5 | resolved | Финальный артефакт сохранён; манифест обновлён последним |
| ожидание-оператора | `resume_phase` | Резолюция оператора привязана к `escalation_id` |
| N → N+1 | Обязательно на границах фаз согласно определению слоя. Быстрый отказ при высоком/критическом Выводе Документатора (перекрёстная проверка не пройдена). Недоступность предварительной проверки → разрешение на обход через council.override_precheck (событие precheck.overridden). Обход записывается в манифест как pre_check_override; разрешает ровно один переход, после чего требуется новая проверка или новый обход. |
| любой | failed | Неустранимая ошибка IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не изменяет состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления `SUBJ-007` для быстрого обзора зарезервирован, но не реализован в MVP.

## Role Status Handling

`extract_role_status()` — единственный источник истины для **консенсуса**. Извлечение с `invalid-format` является блокирующей ошибкой протокола: **сессия** переходит в состояние `blocked-escalation` с `escalation_reason = information-gap`, сгенерированным структурно конвейером извлечения; сырой обзор сохраняется, и **роль** никогда не учитывается как **согласие**. Критический **вывод** с некорректным обоснованием следует тому же принципу недиспровержения (согласно `service-contract/error-management/index.md` §Процесс проверки критических выводов): он понижается до `high` с сохранением исходного текста, а не приводит к полному отклонению обзора. Отсутствие Core-роли означает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Присутствие Core-роли проверяется на каждом пути, а не только перед упрощением. Шлюз pre_check работает независимо от извлечения **статуса роли**, но должен успешно пройти перед любым продвижением протокола.
