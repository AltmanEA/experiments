## `pre_check` Gate

### Scope and Enforcement Point

Контрольная точка `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Она выполняется на уровне 2 (операторская поверхность) в виде синхронного вызова `audit(pre_check=true)` Документатора и возвращает решение вызывающей стороне в рамках того же вызова.

- **Целевая область:** все документы манифеста, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешен только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; runtime считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует процесс соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Разрешить переход |
| Обнаружен любой `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, недоступность службы) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/не читается | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Если Документатор недоступен (вердикт `unavailable`), MVP Модератора НЕ ДОЛЖЕН блокировать indefinite. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Переопределение фиксирует `reason` (произвольный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется при вызове переопределения.
- Переопределение позволяет ровно один последующий переход `Фаза` без новой проверки. После этого перехода следующая граница требует еще одного прохода или нового переопределения.
- Переопределение никогда не обходит наличие Core-Роль, правила Консенсус или шлюзы целостности Эскалация.
