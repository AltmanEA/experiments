## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` — это проверка целостности артефактов документации перед записью переходов состояния протокола. Он выполняется в Слое 2 (поверхности оператора) как синхронный вызов `audit(pre_check=true)` в Документаторе и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевая область:** все документы манифеста, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка применения:** вызывается на каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Ограниченные переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка Консенсуса), `4 → 5` (Резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** surface записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; runtime считывает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его соответствующим образом.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Отсутствуют `high`/`critical` выводы для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН блокировать бесконечно. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- override фиксирует `reason` (свободный текст, объясняющий причину обхода границы).
- override записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется при вызове override.
- override разрешает ровно один последующий переход Фаза без нового аудита. После этого перехода следующая граница требует еще одного прохода или нового override.
- override никогда не обходит присутствие Core-Роль, правила Консенсус или контрольные точки целостности Эскалация.
