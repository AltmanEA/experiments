## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (операторной поверхности) в виде синхронного вызова `audit(pre_check=true)` в Документаторе и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевая область:** все манифест-документы, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе через границу фаз (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Управляемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/неудача/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; runtime считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует её соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Блокировать переход; отправить событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (`unavailable` вердикт), Модератор MVP НЕ ДОЛЖЕН блокировать на неопределенный срок. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Обход фиксирует `reason` (свободный текст, объясняющий, почему был осуществлён обход).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова обхода.
- Обход разрешает ровно один последующий переход между Фазами без новой проверки. После этого перехода следующая граница требует ещё одного прохода или нового обхода.
- Обход никогда не позволяет обойти присутствие Core-Роль, правила Консенсуса или границы целостности Эскалации.
