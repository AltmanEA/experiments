## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через Layer 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает властью принятия решений и не содержит вызовов LLM. Решения по фазе и консенсусу являются детерминированными функциями проверенных выводов ролей; ни одна модель не участвует в потоке управления или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область |
|-----------|---------|-------|
| temperature | 0.1 | обзоры аналитических задач |
| top_p | 0.9 | обзоры аналитических задач |
| frequency_penalty | 0.0 | нейтральный (задан явно, никогда не выводится) |

Белый список по умолчанию управляется централизованно в `defaults/policy.yaml`. Расширение требует PR с обоснованием. Пересматривается ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (точка зрения, обязанности, напоминание о структуре вывода)
- За пределами определения роли и контекста сценария не добавляются несанкционированные инструкции

### Session manifest traceability

Каждая запись сессии содержит раздел "Роль_agent_config", в котором перечислены точные параметры, используемые для каждой активной роли, с возможностью отслеживания до конфигурации сценария → резолюции фабрики → фактической инстанциации агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты предыдущей фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничена только введением акцентов/контекста — поведенческая подмена запрещена.
