## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова метода `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия:** все манифест-документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией состояния новой фазы в Слое 1.
- **Переходы с блокировкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис не работает) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/не читается | `fail` | Блокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать выполнение бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Переопределение записывает `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова переопределения.
- Переопределение разрешает ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует еще одной проверки или нового переопределения.
- Переопределение никогда не обходит присутствие роли Core, правила консенсуса или шлюзы целостности эскалации.
