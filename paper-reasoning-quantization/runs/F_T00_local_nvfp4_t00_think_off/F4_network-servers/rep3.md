# Сетевые серверы

## Система доменных имён (DNS)

Система доменных имён (DNS) — это протокол, посредством которого доменные имена сопоставляются с IP-адресами и наоборот. DNS координируется в масштабах Интернета через довольно сложную систему авторитетных корневых серверов, серверов доменов верхнего уровня (TLD) и других серверов имён меньшего масштаба, которые хранят и кэшируют информацию об отдельных доменах. Для выполнения DNS-запросов на системе не обязательно запускать сервер имён.

В следующей таблице описаны некоторые термины, связанные с DNS:

| Термин | Определение |
| --- | --- |
| Прямая запись DNS | Отображение имён хостов в IP-адреса. |
| Origin | Относится к домену, охваченному в определённом файле зоны. |
| Резолвер | Системный процесс, через который машина запрашивает у сервера имён информацию о зоне. |
| Обратная запись DNS | Отображение IP-адресов в имена хостов. |
| Корневая зона | Начало иерархии зон Интернета. Все зоны находятся под корневой зоной, аналогично тому, как все файлы в файловой системе находятся под корневым каталогом. |
| Зона | Отдельный домен, поддомен или часть DNS, администрируемая одним и тем же органом. |

Примеры зон:

* `.` — так обычно обозначают корневую зону в документации.
* `org.` — домен верхнего уровня (TLD) в рамках корневой зоны.
* `example.org.` — зона в рамках TLD `org.`.
* `1.168.192.in-addr.arpa` — зона, ссылающаяся на все IP-адреса, входящие в пространство адресов `192.168.1.*`.

Как можно видеть, более специфичная часть имени хоста находится слева. Например, `example.org.` более специфична, чем `org.`, так как `org.` более специфична, чем корневая зона. Структура каждой части имени хоста во многом напоминает файловую систему: каталог /dev находится в корне, и так далее.

### Причины для запуска сервера имён

Имена серверов, как правило, бывают двух видов: авторитативные имена серверов и кэширующие (также известные как разрешающие) имена серверов.

Авторитетный сервер имён требуется, когда:

* Кто-то хочет предоставлять DNS-информацию всему миру, отвечая авторитетно на запросы.
* Домен, такой как `example.org`, зарегистрирован, и для имён хостов в нём необходимо назначать IP-адреса.
* Блок IP-адресов требует записей Обратная запись DNS (от IP к имени хоста).
* Резервный или второй сервер имён, называемый подчиненный сервер, будет отвечать на запросы.

Кэширующий сервер имён необходим, когда:

* Локальный DNS-сервер может кэшировать и отвечать быстрее, чем запрос к внешнему серверу имён.

### Конфигурация DNS-сервера

Unbound поставляется в составе базовой системы FreeBSD. По умолчанию он обеспечивает разрешение DNS только для локальной машины. Хотя пакет базовой системы можно настроить для предоставления услуг разрешения за пределами локальной машины, рекомендуется решать такие задачи путем установки Unbound из коллекции портов FreeBSD.

Для включения Unbound добавьте следующую строку в /etc/rc.conf:

```
local_unbound_enable="YES"
```

Любые существующие серверы имён в /etc/resolv.conf будут настроены как серверы пересылки в новой **Конфигурация** Unbound.

> **ПРИМЕЧАНИЕ**
>
> Если какой-либо из перечисленных серверов имен не поддерживает DNSSEC, локальное разрешение имен DNS завершится ошибкой. Обязательно протестируйте каждый сервер имен и удалите те, которые не прошли тест, например, для сервера имен, работающего на `192.168.1.1`.

После того как каждый сервер имён подтвердит поддержку DNSSEC, запустите Unbound:

```shell
# service local_unbound onestart
```
