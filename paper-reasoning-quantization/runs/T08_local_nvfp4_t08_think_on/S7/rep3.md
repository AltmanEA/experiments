## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` — это проверка целостности артефактов документации до фиксации переходов состояния протокола. Он выполняется на Layer 2 (поверхность оператора) в виде синхронного вызова `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевой охват:** все манифест-документы, относящиеся к текущей сессии (идентифицируемые по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией состояния новой фазы в Layer 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешен только при условии, что вердикт — `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; runtime считывает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Отсутствуют `high`/`critical` выводы для целевой области | `pass` | Продолжить переход |
| Обнаружен `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (сетевая ошибка, тайм-аут, недоступность сервиса) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Журнал аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор не может быть достигнут (вердикт `unavailable`), MVP модератора НЕ ДОЛЖЕН бесконечно ожидать. Прошедший аутентификацию `council.override_precheck(reason, operator_id)` может продолжить выполнение, несмотря на сбой:

- Переопределение фиксирует `reason` (произвольный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно при вызове переопределения.
- Переопределение разрешает ровно один последующий переход Фаза без нового аудита. После этого перехода следующий рубеж требует еще одной проверки или нового переопределения.
- Переопределение никогда не обходит наличие Core-Роль, правила Консенсус или шлюзы целостности Эскалация.
