## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Он выполняется на уровне 2 (операторская поверхность) в виде синхронного вызова `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же самого вызова.

- **Область применения:** все манифестные документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе границы фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в слое 1.
- **Ограниченные переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в слой 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует её соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| При наличии любого `high` или `critical` вывода | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, недоступность сервиса) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/не читается | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (`unavailable` вердикт), MVP Модератора не должен бесконечно блокироваться. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Переопределение фиксирует `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется при вызове переопределения.
- Переопределение допускает ровно один последующий переход `Фаза` без новой проверки. После этого перехода следующая граница требует повторного прохода или нового переопределения.
- Переопределение никогда не обходит присутствие `Роль` Core, правила `Консенсус` или шлюзы целостности `Эскалация`.
