## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Он выполняется в Layer 2 (поверхности оператора) в виде синхронного вызова `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевая область:** все документы манифеста, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка применения:** срабатывает при каждом переходе по границе фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей проверке границы и либо продолжает работу, либо блокирует её соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` Выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` Вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сбой сервиса) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН indefinitely блокировать. Аутентифицированный `council.override_precheck(reason, operator_id)` может продолжить выполнение несмотря на сбой:

- Переопределение записывает `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова переопределения.
- Переопределение позволяет ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует еще одного прохождения или нового переопределения.
- Переопределение никогда не обходит наличие Core-роли, правила консенсуса или шлюзы целостности эскалации.
