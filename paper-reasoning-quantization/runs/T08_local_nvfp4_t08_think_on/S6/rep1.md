## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через Layer 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазе и консенсусу представляют собой детерминированные функции проверенных выходов ролей; ни одна модель не участвует в потоке управления или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область применения |
|-----------|---------|-------|
| temperature | 0.1 | analytical-задача обзоры |
| top_p | 0.9 | analytical-задача обзоры |
| frequency_penalty | 0.0 | нейтральный (задан явно, никогда не выводится) |

Белый список по умолчанию управляется централизованно в `defaults/policy.yaml`. Расширение списка требует PR с обоснованием. Проверка проводится ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор Роль соответствует известной Роль из `protocol-core/index.md`
- Шаблон запроса содержит обязательные разделы (перспектива, обязанности, напоминание о структуре вывода)
- Не добавляются несанкционированные инструкции за пределами определения Роль и контекста Сценарий

### Session manifest traceability

Каждая запись сессии включает раздел "Роль_agent_config", содержащий точные параметры, использованные для каждой активной роли, которые можно проследить до конфигурации сценария → резолюции фабрики → фактического инстанцирования агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты предфазы), но НЕ изменяет базовый шаблон запроса роли. Кастомизация запроса ограничена только введением акцентов/контекста — поведенческая подмена запрещена.
