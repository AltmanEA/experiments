## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы Роль, объединяет выводы по `subject_id`, оценивает Консенсус через Layer 0 и маршрутизирует Эскалация. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по Фаза и Консенсус являются детерминированными функциями валидированных выходных данных Роль; никакая модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевого агента из валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указывается вызывающей стороной, либо берется из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все примененные замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область |
|-----------|---------|-------|
| temperature | 0.1 | обзоры аналитических-задач |
| top_p | 0.9 | обзоры аналитических-задач |
| frequency_penalty | 0.0 | нейтрально (задано явно, никогда не выводится) |

По умолчанию белый список централизованно управляется в `defaults/policy.yaml`. Для его расширения требуется PR с обоснованием. Рассматривается ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (точка зрения, обязанности, напоминание о структуре вывода)
- Нет несанкционированных инструкций, добавленных за пределы определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел "Роль_agent_config", перечисляющий точные параметры, используемые для каждой активной роли, которые можно отследить до конфигурации сценария → резолюции фабрики → фактического инстанцирования агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты предфазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничена только акцентом/вставкой контекста — поведенческая подмена запрещена.
