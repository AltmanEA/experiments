## Moderator

Модератор — это детерминированная плоскость управления внутри `orchestrator/`. Он агрегирует статусы Ролей, объединяет выводы по `subject_id`, оценивает Консенсус через Layer 0 и направляет Эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по Фазе и Консенсусу являются детерминированными функциями проверенных выводов Ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указывается вызывающей стороной, ИЛИ берётся из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию фиксируются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область |
|-----------|---------|-------|
| temperature | 0.1 | обзоры аналитических задач |
| top_p | 0.9 | обзоры аналитических задач |
| frequency_penalty | 0.0 | нейтрально (явно задано, никогда не выводится) |

Белый список по умолчанию управляется централизованно в `defaults/policy.yaml`. Для расширения требуется PR с обоснованием. Пересматривается ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон запроса содержит обязательные разделы (перспектива, обязанности, напоминание о структуре вывода)
- Отсутствуют несанкционированные инструкции, добавленные за рамки определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, перечисляющий точные параметры, использованные для каждой активной роли, которые можно отследить до конфигурации сценария → резолюции фабрики → фактической инициализации агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для Сценария (scope Задачи, название Сценария, результаты предфазы), но НЕ изменяет базовый шаблон запроса Роль. Кастомизация запроса ограничена исключительно внесением акцентов/контекста — подмена поведения запрещена.
