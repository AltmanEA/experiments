## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет результаты по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазам и консенсусу являются детерминированными функциями проверенных выходных данных ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии под ключами `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|-------------------------|---------------------|
| temperature | 0.1 | Задача обзора аналитических данных |
| top_p | 0.9 | Задача обзора аналитических данных |
| frequency_penalty | 0.0 | нейтральное (явно задано, никогда не выводится) |

Список разрешённых по умолчанию управляется централизованно в файле `defaults/policy.yaml`. Для его расширения необходимо подготовить pull request с обоснованием. Проверка осуществляется раз в квартал.

### Contract validation hook

После создания, но перед постановкой в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никаких несанкционированных инструкций, добавленных за пределы определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, содержащий точные параметры, используемые для каждой активной роли, которые можно проследить до конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты пред-фазы), но НЕ изменяет базовый шаблон запроса роли. Кастомизация запроса ограничивается только усилением/внедрением контекста — подмена поведения запрещена.
