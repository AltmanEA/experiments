## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы Ролей, объединяет результаты по `subject_id`, оценивает Консенсус через Уровень 0 и маршрутизирует Эскалацию. Он не выполняет свободный текстовый анализ, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения относительно Фазы и Консенсуса являются детерминированными функциями проверенных выводов Ролей; никакая модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо получен из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все примененные замечания по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область применения |
|-----------|--------------|---------------------|
| temperature | 0.1 | Задачи аналитических обзоров |
| top_p | 0.9 | Задачи аналитических обзоров |
| frequency_penalty | 0.0 | нейтральная (явно задача, не выводится) |

Список разрешённых значений по умолчанию управляется централизованно в `defaults/policy.yaml`. Добавление новых элементов требует создания pull request с обоснованием. Пересмотр списка проводится раз в квартал.

### Contract validation hook

После создания, но перед добавлением в очередь, выполните проверку:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит обязательные разделы (перспектива, обязанности, напоминание о структуре вывода)
- Запрещённые инструкции не добавлены за пределами определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии содержит раздел `"role_agent_config"`, в котором указаны точные параметры, использованные для каждой активной роли, что позволяет отследить путь до конфигурации сценария → резолюции фабрики → фактической инициализации агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты предыдущей фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничивается только акцентированием внимания/внедрением контекста — замена поведения запрещена.
