## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (на уровне оператора) в виде синхронного вызова метода `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевой охват:** все манифест-документы, относящиеся к текущей сессии (определяемые `target_id` из активной сценарии).
- **Точка принудительного выполнения:** вызывается на каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Слое 1.
- **Ограниченные переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешен только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Есть любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, таймаут, сервис не работает) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудита Докуматора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (отказ в закрытом режиме согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН блокировать операцию на неопределённый срок. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Переопределение записывает `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова переопределения.
- Переопределение позволяет ровно один последующий переход фазы без нового аудита. После этого перехода следующий рубеж требует еще одной проверки или нового переопределения.
- Переопределение никогда не обходит наличие Роль-ядра, правила Консенсуса или целостности шлюзов Эскалации.
