## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова функции `audit(pre_check=true)` класса Документатор и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Целевой охват:** все манифест-документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в слое 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|---------|---------|----------|
| Нет `high`/`critical` выводов для области действия цели | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; издать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, таймаут, сервис недоступен) | `unavailable` | Заблокировать переход; издать событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/не читается | `fail` | Заблокировать переход (отказ-закрыто согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН блокировать процесс на неопределённый срок. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Фиксируемая запись переопределения содержит `reason` (свободный текст, объясняющий причину обхода контроля).
- Запись переопределения заносится в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова переопределения.
- Переопределение допускает ровно один последующий переход **Фаза** без свежего аудита. После этого перехода следующий контрольный пункт требует повторной проверки или нового переопределения.
- Переопределение никогда не обходит контрольные точки присутствия **Роль**-ядра, правила **Консенсус**а или целостности **Эскалация**.
