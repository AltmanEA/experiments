## Deterministic Control Plane

Поток управления Модератора и каждое решение по Фазе, Консенсусу и Эскалации являются детерминированными функциями от валидированных выводов Роли. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может считывать свободный текст исключительно для отображения; он никогда не интерпретирует его для принятия решений. Загрузка Сценария использует `default-council-session` по умолчанию (см. `scenario/default-council-session.yaml`), если в манифесте Сессии не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` отправка задачи, `2` персональная проверка, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `awaiting-operator`, `resolved`, `failed`.

| From | To | Guard |
|------|----|-------|
| 1 | 2 | Задача проверена; Сценарий загружен; locked_roles согласованы с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствующая роль Core |
| 3 | 4 | Достигнут лимит раундов или нет новых `blocked-in-scope` |
| 3 | 3 | Есть хотя бы один `blocked-in-scope` и остался бюджет целевого раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: `Консенсус` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: `no-consensus` с оставшимся бюджетом → возврат в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: `blocked-Эскалация`; ИЛИ `no-consensus` с исчерпанным бюджетом (`no_consensus_budget` достигает нуля → `blocked-Эскалация` с `Эскалация_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный Артефакт сохранён; манифест обновлён в последнюю очередь |
| awaiting-operator | `resume_phase` | Резолюция оператора привязана к `Эскалация_id` |
| N → N+1 | Обязательно на границах Фаза согласно определению слоя. Быстрый отказ при высоком/критическом Вывод Документатор (percheck failed). Precheck недоступен → override разрешён через council.override_precheck (precheck.overridden event). Override записан в манифест как pre_check_override; разрешает ровно один переход, после которого требуется ещё один проход или новый override. |
| any | failed | Невосстановимая ошибка IO или нарушение протокола |

Только `orchestrator/` переводит фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления `SUBJ-007` для быстрого обзора зарезервирован, но не реализован на этапе MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсуса. Извлечение `invalid-format` представляет собой блокирующую ошибку протокола: Сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, формируемым конвейером извлечения, исходный отзыв сохраняется, а Роль никогда не засчитывается как `Согласие`. Критический Вывод с некорректным обоснованием подчиняется тому же принципу сохранения без отклонения (согласно `service-contract/error-management/index.md` §Critical Вывод Validation Process): он понижается до `high` с сохранением исходного текста, вместо того чтобы приводить к немедленному отклонению рецензии. Отсутствие Роль Core означает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз pre_check функционирует независимо от извлечения Статуса роли, но должен успешно завершиться перед любым продвижением протокола.
