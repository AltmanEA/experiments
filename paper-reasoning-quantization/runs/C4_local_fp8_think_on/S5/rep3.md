## Deterministic Control Plane

Поток управления Модератора и каждое решение по Фазе, Консенсусу и Эскалации являются детерминированными функциями проверенных выходов Ролей. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может считывать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка Сценария откатывается к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте Сессии не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` подача задачи, `2` индивидуальный обзор, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `awaiting-operator`, `resolved`, `failed`.

| Откуда | Куда | Ограничение |
|------|----|-------|
| 1 | 2 | Задача проверена; Сценарий загружен; locked_roles согласованы с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствующая роль Core |
| 3 | 4 | Достигнут лимит раундов или нет новых `blocked-in-scope` |
| 3 | 3 | Есть хотя бы один `blocked-in-scope` и остаётся бюджет целевого раунда |
| 4 | 5 | Согласно таблице §Outcome-to-Transition в protocol-core: `консенсус` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице §Outcome-to-Transition в protocol-core: `no-консенсус` с оставшимся бюджетом → повторный вход в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице §Outcome-to-Transition в protocol-core: `blocked-эскалация`; ИЛИ `no-консенсус` с исчерпанным бюджетом (`no_consensus_budget` достигает нуля → `blocked-эскалация` с `эскалация_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный Артефакт сохранён; манифест обновлён в последнюю очередь |
| awaiting-operator | `resume_phase` | Резолюция оператора привязана к `эскалация_id` |
| N → N+1 | Обязательно на границах Фаза согласно определению слоя. Быстрый отказ при высоком/критическом Вывод Документатор (percheck failed). Precheck недоступен → разрешение на отмену через council.override_precheck (precheck.overridden event). Отмена записывается в манифест как pre_check_override; разрешает ровно один переход, после которого требуется ещё один проход или новая отмена. |
| any | failed | Неисправимая ошибка IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления для быстрого обзора `SUBJ-007` зарезервирован, но не реализован в MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсуса. Извлечение с `invalid-format` представляет собой блокирующую ошибку протокола: Сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, сгенерированным структурно конвейером извлечения, сырой отзыв сохраняется, а Роль никогда не учитывается как `Согласие`. Критический Вывод с недействительным обоснованием следует тому же принципу непринятия отказа (согласно `service-contract/error-management/index.md` §Critical Вывод Validation Process): он понижается до `high` с сохранением исходного текста, вместо того чтобы вызывать полный отказ от отзыва. Отсутствие Роль Core означает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз pre_check работает независимо от извлечения Статуса роли, но должен успешно пройти перед любым продвижением протокола.
