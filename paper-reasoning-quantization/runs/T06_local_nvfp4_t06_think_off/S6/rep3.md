## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет результаты по `subject_id`, оценивает консенсус через Уровень 0 и маршрутизирует эскалацию. Он не выполняет свободную интерпретацию текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазам и консенсусу являются детерминированными функциями проверенных выходов ролей; ни одна модель не участвует в управлении потоком выполнения или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применяемые замечания по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область применения |
|-----------|---------|-------|
| temperature | 0.1 | analytical-task reviews |
| top_p | 0.9 | analytical-task reviews |
| frequency_penalty | 0.0 | neutral (explicitly set, never inferred) |

Список разрешённых значений (whitelist) по умолчанию управляется централизованно в файле `defaults/policy.yaml`. Для расширения списка необходимо создать pull request с обоснованием. Пересмотр осуществляется ежеквартально.

### Contract validation hook

После создания, но до добавления в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никаких несанкционированных инструкций, добавленных за пределы определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, в котором указаны точные параметры, использованные для каждой активной роли, что позволяет отследить их от конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты до фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничена только акцентированием внимания/внедрением контекста — подмена поведения запрещена.
