## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед тем, как будут зафиксированы переходы состояния протокола. Он выполняется на уровне 2 (поверхность оператора) как синхронный вызов метода `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия:** все манифестные документы, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка принуждения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Слое 1.
- **Переходы с контролем:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (принятие резолюции). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей границе оценки и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевого диапазона | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/не читается | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать процесс на неопределённый срок. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Записи обхода содержат `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход допускает ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует еще одного прохода или нового обхода.
- Обход никогда не обходит наличие роли Core, правила консенсуса или шлюзы целостности эскалации.
