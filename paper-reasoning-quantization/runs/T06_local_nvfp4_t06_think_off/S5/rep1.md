## Deterministic Control Plane

**Модератор** управляет потоком выполнения, и каждое решение по **фазе**, **консенсусу** и **эскалации** является детерминированной функцией от валидированных выходов **ролей**. Ни одна LLM не участвует в управлении потоком выполнения или проверке безопасности. **Модератор** может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка **сценария** переходит к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте **сессии** не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` отправка задачи, `2` индивидуальная проверка, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, а также `ожидание-оператора`, `разрешено`, `неудача`.

| Откуда | Куда | Охранный механизм |
|------|----|-------|
| 1 | 2 | Задача проверена; сценарий загружен; locked_roles разрешены в соответствии с operator_approval согласно `service-contract/index.md` §Сессия Манифест |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | ожидание-оператора | Любой статус `invalid-format` или отсутствие роли Core |
| 3 | 4 | Достигнут лимит раундов, или нет новых `blocked-in-scope` |
| 3 | 3 | Как минимум один `blocked-in-scope` и остаётся целевой бюджет раунда |
| 4 | 5 | Согласно таблице §Outcome-to-Transition протокольного ядра: `consensus` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице §Outcome-to-Transition протокольного ядра: `no-consensus` с оставшимся бюджетом → повторный вход в Фазу 3; декрементирует `no_consensus_budget`. |
| 4 | ожидание-оператора | Согласно таблице §Outcome-to-Transition протокольного ядра: `blocked-escalation`; ИЛИ `no-consensus` с исчерпанным бюджетом (`no_consensus_budget` достигает нуля → `blocked-escalation` с `escalation_reason = information-gap`) → `ожидание-оператора` |
| 5 | resolved | Финальный артефакт сохранён; манифест обновлён в последнюю очередь |
| ожидание-оператора | `resume_phase` | Резолюция оператора связана с `escalation_id` |
| N → N+1 | Обязательно на границах фаз согласно определению слоя. Быстрый отказ при обнаружении критического Вывода Документатора (перечек не прошёл). Недоступность предварительной проверки → разрешение обхода через council.override_precheck (событие precheck.overridden). Обход записывается в манифест как pre_check_override; разрешает ровно один переход, после чего требуется ещё один проход или новое обхождение. |
| любой | failed | Неисправимая ошибка ввода-вывода или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления `SUBJ-007` для быстрого обзора зарезервирован, но не реализован на этапе MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для **консенсуса**. Извлечение с `invalid-format` представляет собой блокирующую ошибку протокола: **сессия** переходит в состояние `blocked-escalation` с `escalation_reason = information-gap`, который структурно генерируется конвейером извлечения; сырой обзор сохраняется, а **роль** никогда не считается как `agree`. Критический **вывод** с недействительным обоснованием следует тому же принципу отказа от отклонения (согласно `service-contract/error-management/index.md` §Процесс проверки критических выводов): он понижается до `high` с сохранением исходного текста, а не вызывает полное отклонение обзора. Отсутствие **роли** ядра приводит к `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие **роли** ядра проверяется на каждом пути, а не только перед упрощением. Ворота `pre_check` работают независимо от извлечения **статуса роли**, но должны быть успешно пройдены перед любым продвижением протокола.
