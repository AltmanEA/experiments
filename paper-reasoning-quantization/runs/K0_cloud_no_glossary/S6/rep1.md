## Moderator

Модератор — это детерминированная управляющая плоскость, расположенная внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет результаты по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию свободного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазам и консенсусу являются детерминированными функциями проверенных выходных данных ролей; ни одна модель не участвует в управлении потоком выполнения или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного значения, видимого в манифесте сессии. Никаких скрытых значений по умолчанию. Все применённые значения по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|----------------------|---------------------|
| temperature | 0.1 | аналитические задачи, обзоры |
| top_p | 0.9 | аналитические задачи, обзоры |
| frequency_penalty | 0.0 | нейтральная (явно задано, никогда не выводится) |

Список разрешённых значений по умолчанию управляется централизованно в файле `defaults/policy.yaml`. Внесение изменений требует оформления запроса на слияние (PR) с обоснованием. Пересмотр осуществляется ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Запрещённые инструкции не добавляются за пределы определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии содержит раздел `"role_agent_config"`, в котором перечислены точные параметры, использованные для каждой активной роли, с возможностью проследить их происхождение от конфигурации сценария → разрешения фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты предшествующей фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничивается только акцентированием внимания и внедрением контекста — подмена поведения запрещена.
