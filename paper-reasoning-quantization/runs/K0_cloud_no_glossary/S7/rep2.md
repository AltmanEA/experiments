## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова метода `audit(pre_check=true)` компонента Documenter и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все манифестные документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка применения:** вызывается на каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в слое 1.
- **Переходы с блокировкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (разрешение). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Для целевой области отсутствуют результаты `high`/`critical` | `pass` | Продолжить переход |
| Присутствует любой результат `high` или `critical` | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать неопределённо. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Запись об обходе содержит `reason` (свободный текст, объясняющий причину обхода шлюза).
- Информация об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова операции обхода.
- Обход позволяет совершить ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует повторной проверки или нового обхода.
- Обход никогда не позволяет игнорировать требования присутствия ролей ядра, правила консенсуса или шлюзы целостности эскалации.
