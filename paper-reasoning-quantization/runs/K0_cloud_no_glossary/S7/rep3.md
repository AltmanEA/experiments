## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед тем, как будут зафиксированы переходы состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова метода `audit(pre_check=true)` компонента Documenter и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все документы манифеста, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается на каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Слое 1.
- **Переходы с блокировкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (разрешение). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границы и либо продолжает выполнение, либо блокирует его.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` находок для целевой области | `pass` | Продолжить переход |
| Присутствует любая `high` или `critical` находка | `fail` | Блокировать переход; отправить событие `precheck.failed` |
| Documenter недоступен (ошибка сети, таймаут, сервис недоступен) | `unavailable` | Блокировать переход; отправить событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудитов Documenter отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖНОВ блокировать неопределённо долго. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Запись об обходе содержит поле `reason` (свободный текст, объясняющий причину обхода шлюза).
- Информация об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время выполнения операции обхода.
- Обход позволяет совершить ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует повторного прохода или нового обхода.
- Обход никогда не позволяет игнорировать требования присутствия ролей ядра, правила консенсуса или шлюзы целостности эскалации.
