## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` — это проверка целостности артефактов документации до фиксации переходов состояний протокола. Он выполняется на Уровне 2 (поверхность оператора) в виде синхронного вызова `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все манифестные документы, относящиеся к текущей сессии (идентифицируются по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе через границу фаза (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фаза в Layer 1.
- **Переходы с блокировкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсус), `4 → 5` (резолюция). Переход разрешен только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифест `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения читает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокируется соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сбой службы) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/нечитаем | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (`unavailable` вердикт), MVP Модератора НЕ ДОЛЖЕН блокироваться бесконечно. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на ошибку:

- Обход фиксирует `reason` (свободный текст, объясняющий, почему контрольная точка была обойдена).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход разрешает ровно один последующий переход Фаза без нового аудита. После этого перехода следующая граница требует ещё одного прохода или нового обхода.
- Обход никогда не обходит присутствие Core-Роль, правила Консенсус или контрольные точки целостности Эскалация.
