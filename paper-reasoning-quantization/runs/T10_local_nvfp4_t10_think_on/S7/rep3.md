## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Он выполняется на уровне 2 (интерфейс оператора) в виде синхронного вызова `audit(pre_check=true)` в Документаторе и возвращает вердикт вызывающему коду в рамках того же самого вызова.

- **Целевой охват:** все манифест-документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешен только при результате `pass`.
- **Передача вердикта в Layer 1:** surface записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; runtime считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует её соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| При отсутствии `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| При наличии `high` или `critical` вывода | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, таймаут, сервис недоступен) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН бесконечно блокироваться. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Обход сохраняет `reason` (свободный текст, объясняющий, почему гейт был обойден).
- Обход записывается в манифест через поле `pre_check_override`.
- Синхронно генерируется событие `precheck.overridden` во время вызова обхода.
- Обход разрешает ровно один последующий переход Фазы без нового аудита. После этого перехода следующий барьер требует повторного прохождения или нового обхода.
- Обход никогда не обходит наличие Core-роль, правила Консенсус или гейты целостности Эскалация.
