## Deterministic Control Plane

Поток управления Модератора, а также каждая фаза, консенсус и решение об эскалации являются детерминированными функциями от валидированных выходов ролей. Ни одна LLM не участвует в управлении потоком или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. При загрузке Сценария применяется значение по умолчанию `default-callback-session` (см. `scenario/default-callback-session.yaml`), если в манифесте сессии не указан явный `scenario_id`.

## Phase State Machine

`Состояния: \`1\` отправка задачи, \`2\` индивидуальная проверка, \`3\` обсуждение, \`4\` проверка консенсуса, \`5\` резолюция, плюс \`awaiting-operator\`, \`resolved\`, \`failed\`.`

| Откуда | Куда | Guard |
|------|----|-------|
| 1 | 2 | Задача проверена; Сценарий загружен; locked_roles согласованы с operator_approval согласно \`service-contract/index.md\` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет \`RoleStatus\` со значением \`extraction = parsed\` |
| 2 | awaiting-operator | Любой статус \`invalid-format\` или отсутствующая роль Core |
| 3 | 4 | Достигнут лимит раундов или нет новых \`blocked-in-scope\` |
| 3 | 3 | Присутствует как минимум один \`blocked-in-scope\` и остаётся бюджет целевого раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: \`Консенсус\` или \`conditional\` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: \`no-Консенсус\` с оставшимся бюджетом → возврат в Фаза 3; уменьшает \`no_consensus_budget\`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: \`blocked-Эскалация\`; ИЛИ \`no-Консенсус\` с исчерпанным бюджетом (\`no_consensus_budget\` достигает нуля → \`blocked-Эскалация\` с \`escalation_reason = information-gap\`) → \`awaiting-operator\` |
| 5 | resolved | Финальный Артефакт сохранён; manifest обновлён последним |
| awaiting-operator | \`resume_phase\` | Резолюция оператора привязана к \`escalation_id\` |
| N → N+1 | Обязательно на границах Фаза согласно определению уровня. Быстрый отказ при высоком/критическом Вывод Документатор (percheck не прошёл). Precheck недоступен → override разрешён через council.override_precheck (precheck.overridden event). Override записывается в manifest как pre_check_override; допускает ровно один переход, после чего требуется ещё один проход или новый override. |
| any | failed | Невосстанавливаемое IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления для быстрой проверки `SUBJ-007` зарезервирован, но не реализован на этапе MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсуса. Извлечение с форматом `invalid-format` представляет собой блокирующую ошибку протокола: Сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, сформированным конвейером извлечения, исходный отзыв сохраняется, а Роль никогда не засчитывается как `Согласие`. Критический Вывод с некорректным обоснованием подчиняется тому же принципу недоотклонения (согласно `service-contract/error-management/index.md` §Процесс проверки критических Выводов): он понижается до `high` с сохранением исходного текста, а не приводит к полному отклонению обзора. Отсутствие Роль Core вызывает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз `pre_check` функционирует независимо от извлечения Статуса роли, но должен успешно пройти перед любым продвижением протокола.
