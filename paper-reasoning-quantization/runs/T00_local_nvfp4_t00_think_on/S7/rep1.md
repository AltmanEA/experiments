## `pre_check` Gate

### Scope and Enforcement Point

Контрольная точка `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояний протокола. Он выполняется на уровне 2 (интерфейс оператора) в виде синхронного вызова `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все манифест-документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается на каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Переходы с контролем:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей проверке границы и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Разрешить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, недоступность сервиса) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Если Документатор недоступен (вердикт `unavailable`), MVP модератора НЕ ДОЛЖЕН блокировать бесконечно. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Обход фиксирует `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход разрешает ровно один последующий переход фазы без новой проверки. После этого перехода следующая граница требует еще одного прохода или нового обхода.
- Обход никогда не обходит присутствие Core-роли, правила консенсуса или шлюзы целостности эскалации.
