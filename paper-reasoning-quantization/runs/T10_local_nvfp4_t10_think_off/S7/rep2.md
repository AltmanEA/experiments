## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документирования перед фиксацией переходов состояния протокола. Он выполняется в слое 2 (интерфейс оператора) в виде синхронного вызова `audit(pre_check=true)` метода Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все документы манифеста, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждой границе перехода фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией состояния новой фазы в Слое 1.
- **Переходы с ограничениями:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при результате `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либоProceeds, либо блокирует выполнение соответственно.

### Verdict Logic

| Состояние | Решение | Действие |
|-----------|---------|--------|
| Отсутствие `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Наличие любого `high` или `critical` вывода | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, таймаут, сервис не работает) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/не читается | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор MVP НЕ ДОЛЖЕН блокировать процесс бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на ошибку:

- Записи об отмене `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Отмена записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно испускается во время вызова отмены.
- Отмена допускает ровно один последующий переход фазы без новой проверки. После этого перехода следующий граница требует еще одной проверки или новой отмены.
- Отмена никогда не обходит присутствие роли Core, правила консенсуса или шлюзы целостности эскалации.
