## `pre_check` Gate

### Scope and Enforcement Point

Ворота `pre_check` представляют собой проверку целостности артефактов документации перед тем, как будут зафиксированы переходы состояния протокола. Они работают на уровне 2 (поверхность оператора) как синхронный вызов `audit(pre_check=true)` в Документаторе и возвращают вердикт вызывающей стороне в рамках того же вызова.

- **Область применения:** все манифест-документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается на каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед сохранением нового состояния фазы в Слое 1.
- **Барьерные переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения читает это поле/событие при следующей оценке границы и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|---------|---------|----------|
| Для области целевого объекта отсутствуют выводы уровня `high`/`critical` | `pass` | Продолжить переход |
| Присутствует любой вывод уровня `high` или `critical` | `fail` | Заблокировать переход; отправить событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, сервис недоступен) | `unavailable` | Заблокировать переход; отправить событие `precheck.unavailable` (см. Режим обхода ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (приговор `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать операцию бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на ошибку:

- Записи обхода содержат `reason` (свободный текст, объясняющий, почему был обойден шлюз).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова обхода.
- Обход разрешает ровно один последующий переход фазы без свежей проверки. После этого перехода следующий граничный узел требует еще одной проверки или нового обхода.
- Обход никогда не обходит проверки присутствия роли Core, правил консенсуса или целостности шлюзов эскалации.
