## `pre_check` Gate

### Scope and Enforcement Point

Ворота `pre_check` представляют собой проверку целостности артефактов документации до коммита переходов состояния протокола. Она выполняется на уровне 2 (поверхности оператора) как синхронный вызов метода `audit(pre_check=true)` у **Документатора** и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия цели:** все манифест-документы, относящиеся к текущей сессии (идентифицируются по `target_id` из активного сценария).
- **Точка принудительного исполнения:** вызывается при каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Переходы с гейтами:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (принятие резолюции). Переход разрешён только в случае результата `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границ и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Отсутствуют `high`/`critical` выводы для целевого объема | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (сетевая ошибка, таймаут, сервис не работает) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. Режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (отказ закрыт согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), Модератор в рамках MVP НЕ ДОЛЖЕН блокировать выполнение бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на неудачу:

- В записи об обходе указывается `reason` (свободный текст, объясняющий причину обхода шлюза).
- Информация об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется в момент вызова обхода.
- Обход позволяет ровно один последующий переход фазы без свежего аудита. После этого перехода для следующего рубежа требуется ещё одна проверка или новый обход.
- Обход никогда не позволяет обойти наличие роли Core, правила консенсуса или шлюзы целостности эскалации.
