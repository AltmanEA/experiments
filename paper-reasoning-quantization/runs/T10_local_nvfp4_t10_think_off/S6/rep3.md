## Moderator

Модератор — это детерминированная управляющая плоскость внутри каталога `orchestrator/`. Он агрегирует состояния ролей, объединяет результаты по `subject_id`, оценивает консенсус через Layer 0 и маршрутизирует эскалацию. Модератор не осуществляет свободного текстового толкования, не обладает полномочиями для принятия решений и не выполняет вызовов LLM. Решения по фазам и консенсусу являются детерминированными функциями проверенных выходов ролей; никакие модели не участвуют в управлении потоком выполнения или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область видимости |
|-----------|---------|-------|
| температура | 0.1 | аналитическая-задача отзывы |
| top_p | 0.9 | аналитическая-задача отзывы |
| frequency_penalty | 0.0 | нейтральный (явно установлен, никогда не выводится) |

Список разрешённых (whitelist) значений по умолчанию централизованно управляется через файл `defaults/policy.yaml`. Для его расширения необходимо создать запрос на слияние (PR) с обоснованием. Пересмотр происходит ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит обязательные разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никакие несанкционированные инструкции не добавлены помимо определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, в котором указаны точные параметры, использованные для каждой активной роли, с возможностью проследить цепочку от конфигурации сценария → резолюции фабрики → фактического создания агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты предшествующей фазы), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничивается исключительно акцентированием внимания / внедрением контекста — подстановка поведения запрещена.
