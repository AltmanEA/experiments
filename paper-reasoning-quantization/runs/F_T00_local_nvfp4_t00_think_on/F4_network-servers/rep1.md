# Сеть Серверы

## Система доменных имён (DNS)

Система доменных имён (DNS) — это протокол, посредством которого доменные имена сопоставляются с IP-адресами, и наоборот. DNS координируется в масштабах Интернета через довольно сложную систему авторитетных корневых, домен верхнего уровня (TLD) и других серверов меньшего масштаба, которые размещают и кэшируют информацию об отдельных доменах. Для выполнения DNS-запросов на системе не обязательно запускать сервер имён.

В следующей таблице описаны некоторые термины, связанные с DNS:

| Термин | Определение |
| --- | --- |
| Прямая запись DNS | Сопоставление имён хостов с IP-адресами. |
| Начало | Относится к домену, который охватывается данным файлом зоны. |
| резолвер | Системный процесс, с помощью которого машина запрашивает у сервера имён информацию о зоне. |
| Обратная запись DNS | Сопоставление IP-адресов с именами хостов. |
| корневая зона | Начало иерархии зон Интернета. Все зоны находятся под корневой зоной, аналогично тому, как все файлы в файловой системе находятся в корневом каталоге. |
| зона | Отдельный домен, поддомен или часть DNS, управляемая одним и тем же органом. |

Примеры зон:

* `.` — так обычно называют корневую зону в документации.
* `org.` — это домен верхнего уровня (TLD) в пределах корневой зоны.
* `example.org.` — это зона под TLD `org.`.
* `1.168.192.in-addr.arpa` — это зона, ссылающаяся на все IP-адреса, которые входят в адресное пространство `192.168.1.*`.

Как можно видеть, более специфичная часть имени хоста находится слева. Например, `example.org.` является более специфичной, чем `org.`, поскольку `org.` более специфична, чем корневая зона. Структура каждой части имени хоста во многом напоминает файловую систему: каталог /dev находится в корне, и так далее.

### Причины запуска сервера имён

Серверы имён, как правило, бывают двух видов: авторитетные серверы имён и кэширующие (также известные как разрешающие) серверы имён.

Авторитетный сервер имён требуется, когда:

* Один хочет предоставлять DNS-информацию всему миру, отвечая авторитетно на запросы.
* Домен, такой как `example.org`, зарегистрирован, и для него необходимо назначить IP-адреса для имён хостов.
* Блок IP-адресов требует записей Обратная запись DNS (IP в имя хоста).
* Резервный или второй сервер имён, называемый подчиненный сервер, будет отвечать на запросы.

Кэширующий сервер имён необходим, когда:

* Локальный DNS-сервер может кэшировать и отвечать быстрее, чем запрос к внешнему серверу имён.

### Конфигурация сервера DNS

Unbound поставляется в составе базовой системы FreeBSD. По умолчанию он обеспечивает разрешение DNS только для локальной машины. Хотя пакет базовой системы можно настроить для предоставления услуг разрешения за пределами локальной машины, рекомендуется решать такие задачи, установив Unbound из коллекции портов FreeBSD.

Чтобы включить Unbound, добавьте следующее в /etc/rc.conf:

```
local_unbound_enable="YES"
```

Любые существующие серверы имен в /etc/resolv.conf будут настроены как серверы пересылки в новой конфигурации Unbound.

> **ПРИМЕЧАНИЕ**
>
> Если какой-либо из указанных серверов имен не поддерживает DNSSEC, локальное разрешение DNS завершится ошибкой. Обязательно проверьте каждый сервер имен и удалите те, которые не прошли проверку, например, для сервера имен, работающего на `192.168.1.1`.

После подтверждения поддержки DNSSEC каждым сервером имён запустите Unbound:

```shell
# service local_unbound onestart
```
