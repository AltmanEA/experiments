## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова метода `audit(pre_check=true)` у Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия цели:** все манифестные документы, относящиеся к текущей сессии (определяются по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается на каждом переходе между фазами (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Слое 1.
- **Переходы с контролем:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Слой 1:** поверхность записывает результат вердикта (pass/fail/причина) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие на следующей оценке границы и либо продолжает работу, либо блокирует её.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, таймаут, сервис недоступен) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), модератор MVP НЕ ДОЛЖЕН блокировать процесс бесконечно. Аутентифицированный вызов `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Записи обхода содержат `reason` (свободный текст, объясняющий причину обхода шлюза).
- Информация об обходе записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется во время вызова обхода.
- Обход разрешает ровно один последующий переход фазы без новой проверки. После этого перехода следующий рубеж требует повторного прохода или нового обхода.
- Обход никогда не обходит правила присутствия роли Core, правила консенсуса или шлюзы целостности эскалации.
