# Серверы сети

## Система доменных имён (DNS)

Система доменных имён (DNS) — это протокол, посредством которого доменные имена сопоставляются с IP-адресами и наоборот. DNS координируется в масштабах Интернета через довольно сложную систему авторитетных корневых, домен верхнего уровня (TLD) и других серверов меньшего масштаба, которые хранят и кэшируют информацию об отдельных доменах. Для выполнения DNS-запросов в системе не обязательно запускать сервер имён.

В следующей таблице описаны некоторые термины, связанные с DNS:

| Термин | Определение |
| --- | --- |
| Прямая запись DNS | Отображение имён хостов в IP-адреса. |
| Origin | Относится к домену, охватываемому конкретным файлом зоны. |
| Резолвер | Системный процесс, через который машина запрашивает у сервера имён информацию о зоне. |
| Обратная запись DNS | Отображение IP-адресов в имена хостов. |
| Корневая зона | Начало иерархии зон Интернета. Все зоны находятся под корневой зоной, аналогично тому, как все файлы в файловой системе находятся в корневом каталоге. |
| Зона | Отдельный домен, поддомен или часть DNS, администрируемая одним и тем же органом. |

Примеры зон:

* `.` — так обычно называют корневую зону в документации.
* `org.` — это домен верхнего уровня (TLD) в рамках корневой зоны.
* `example.org.` — это зона в рамках TLD `org.`.
* `1.168.192.in-addr.arpa` — это зона, ссылающаяся на все IP-адреса, которые входят в адресное пространство `192.168.1.*`.

Как видно, более специфичная часть имени хоста расположена слева. Например, `example.org.` более специфична, чем `org.`, поскольку `org.` более специфична, чем корневая зона. Структура каждой части имени хоста во многом напоминает файловую систему: каталог /dev находится в корне, и так далее.

### Причины запуска сервера имён

Серверы имён обычно делятся на два типа: авторитетные серверы имён и кэширующие (также известные как разрешающие) серверы имён.

Авторитетный сервер имён необходим, когда:

* Один хочет предоставлять DNS-информацию всему миру, отвечая авторитетно на запросы.
* Домен, такой как `example.org`, зарегистрирован, и к нему нужно назначить IP-адреса для имён хостов.
* Блок IP-адресов требует Обратная запись DNS (IP к имени хоста).
* Резервный или второй сервер имён, называемый подчиненный сервер, будет отвечать на запросы.

Кэширующий сервер имён нужен, когда:

* Локальный DNS-сервер может кэшировать и отвечать быстрее, чем при запросе к внешнему серверу имён.

### Конфигурация сервера DNS

Unbound предоставляется в базовой системе FreeBSD. По умолчанию он обеспечивает разрешение DNS только для локальной машины. Хотя пакет базовой системы можно настроить для предоставления услуг разрешения за пределами локальной машины, рекомендуется решать такие задачи путем установки Unbound из коллекции портов FreeBSD.

Чтобы включить Unbound, добавьте следующее в /etc/rc.conf:

```
local_unbound_enable="YES"
```

Любые существующие серверы имен из /etc/resolv.conf будут настроены как серверы пересылки в новой конфигурации Unbound.

> **ПРИМЕЧАНИЕ**
>
> Если какой-либо из указанных серверов имен не поддерживает DNSSEC, локальное разрешение DNS завершится ошибкой. Обязательно протестируйте каждый сервер имен и исключите те, которые не прошли проверку, например, для сервера имен, работающего на `192.168.1.1`.

После подтверждения поддержки DNSSEC каждым сервером имен запустите Unbound:

```shell
# service local_unbound onestart
```
