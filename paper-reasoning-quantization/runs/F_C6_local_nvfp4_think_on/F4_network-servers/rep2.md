# Сеть Серверы

## Система доменных имён (DNS)

Система доменных имён (DNS) — это протокол, посредством которого доменные имена сопоставляются с IP-адресами, и наоборот. DNS координируется в масштабах Интернета через довольно сложную систему авторитетных корневых, домен верхнего уровня (TLD) и других серверов меньшего масштаба, которые хранят и кэшируют информацию об отдельных доменах. Для выполнения DNS-запросов в системе не обязательно запускать сервер имён.

В следующей таблице описаны некоторые термины, связанные с DNS:

| Термин | Определение |
| --- | --- |
| Прямая запись DNS | Отображение имён хостов в IP-адреса. |
| Начало | Относится к домену, охваченному конкретным файлом зоны. |
| Резолвер | Системный процесс, с помощью которого машина запрашивает у сервера имён информацию о зоне. |
| Обратная запись DNS | Отображение IP-адресов в имена хостов. |
| Корневая зона | Начало иерархии зон Интернета. Все зоны находятся в пределах корневой зоны, аналогично тому, как все файлы в файловой системе находятся в корневом каталоге. |
| Зона | Отдельный домен, поддомен или часть DNS, администрируемая одним и тем же органом. |

Примеры зон:

* `.` — так обычно обозначают корневую зону в документации.
* `org.` — это домен верхнего уровня (TLD) под корневой зоной.
* `example.org.` — это зона под TLD `org.`.
* `1.168.192.in-addr.arpa` — это зона, ссылающаяся на все IP-адреса, которые входят в адресное пространство `192.168.1.*`.

Как можно видеть, более конкретная часть имени хоста находится слева. Например, `example.org.` более конкретна, чем `org.`, так как `org.` более конкретна, чем корневая зона. Структура каждой части имени хоста во многом напоминает файловую систему: каталог /dev находится в корне, и так далее.

### Причины запуска сервера имён

Серверы имен обычно делятся на два типа: авторитетные серверы имен и кэширующие (также известные как разрешающие) серверы имен.

Авторитетный сервер имён необходим, когда:

* Один хочет предоставлять DNS-информацию всему миру, отвечая авторитетно на запросы.
* Домен, такой как `example.org`, зарегистрирован, и для него необходимо назначить IP-адреса для имён хостов.
* Блок IP-адресов требует записей Обратная запись DNS (IP в имя хоста).
* Резервный или второй сервер имён, называемый подчиненный сервер, будет отвечать на запросы.

Кэширующий сервер имён требуется, когда:

* Локальный DNS-сервер может кэшировать и отвечать быстрее, чем запрос к внешнему серверу имён.

### Конфигурация DNS-сервера

Unbound поставляется в составе базовой системы FreeBSD. По умолчанию он обеспечивает разрешение DNS только для локальной машины. Хотя пакет базовой системы можно настроить для предоставления услуг разрешения за пределами локальной машины, рекомендуется решать такие задачи путем установки Unbound из коллекции портов FreeBSD.

Чтобы включить Unbound, добавьте следующее в /etc/rc.conf:

```
local_unbound_enable="YES"
```

Любые существующие серверы имен в /etc/resolv.conf будут настроены как серверы пересылки в новой Unbound конфигурации.

> **ПРИМЕЧАНИЕ**
>
> Если какой-либо из указанных серверов имен не поддерживает DNSSEC, локальное разрешение имен DNS завершится ошибкой. Обязательно проверьте каждый сервер имен и удалите те, которые не прошли проверку, например, для сервера имен, работающего на `192.168.1.1`.

После подтверждения поддержки DNSSEC каждым сервером имён запустите Unbound:

```shell
# service local_unbound onestart
```
