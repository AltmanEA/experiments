# Серверы сети

## Система доменных имён (DNS)

Система доменных имён (DNS) — это протокол, посредством которого доменные имена сопоставляются с IP-адресами, и наоборот. DNS координируется во всём Интернетe через довольно сложную систему авторитетных корневых, домен верхнего уровня (TLD) и других серверов имён меньшего масштаба, которые хранят и кэшируют информацию об отдельных доменах. Для выполнения DNS-запросов в системе не обязательно запускать сервер имён.

В следующей таблице описаны некоторые термины, связанные с DNS:

| Термин | Определение |
| --- | --- |
| Прямая запись DNS | Сопоставление имён хостов с IP-адресами. |
| Начало | Относится к домену, описанному в конкретном файле зоны. |
| резолвер | Системный процесс, с помощью которого машина запрашивает у сервера имён информацию о зоне. |
| Обратная запись DNS | Сопоставление IP-адресов с именами хостов. |
| корневая зона | Начало иерархии зон Интернета. Все зоны находятся под корневой зоной, аналогично тому, как все файлы в файловой системе находятся в корневом каталоге. |
| зона | Отдельный домен, поддомен или часть DNS, управляемая одним и тем же органом. |

Примеры зон:

* `.` так обычно обозначается корневая зона в документации.
* `org.` — это домен верхнего уровня (TLD) в корневой зоне.
* `example.org.` — это зона в рамках домена верхнего уровня `org.`.
* `1.168.192.in-addr.arpa` — это зона, ссылающаяся на все IP-адреса, которые входят в пространство адресов `192.168.1.*`.

Как видно, более конкретная часть имени хоста расположена слева. Например, `example.org.` более конкретна, чем `org.`, поскольку `org.` более конкретна, чем корневая зона. Структура каждой части имени хоста во многом напоминает файловую систему: каталог /dev находится внутри корня, и так далее.

### Причины запуска сервера имён

Серверы имён обычно бывают двух видов: авторитетные серверы имён и кэширующие (также известные как разрешающие) серверы имён.

Авторитетный сервер имён требуется, когда:

* Один хочет предоставлять DNS-информацию всему миру, отвечая авторитетно на запросы.
* Домен, такой как `example.org`, зарегистрирован, и для него необходимо назначить IP-адреса для имён хостов.
* Блок IP-адресов требует записей Обратная запись DNS (IP к имени хоста).
* Резервный или второй сервер имён, называемый подчиненный сервер, будет отвечать на запросы.

Кэширующий сервер имён необходим, когда:

* Локальный DNS-сервер может кэшировать и отвечать быстрее, чем запрос к внешнему серверу имён.

### Конфигурация DNS-сервера

Unbound поставляется в составе базовой системы FreeBSD. По умолчанию он обеспечивает разрешение DNS только для локальной машины. Хотя пакет базовой системы можно настроить для предоставления услуг разрешения за пределами локальной машины, рекомендуется решать такие задачи путем установки Unbound из коллекции портов FreeBSD.

Чтобы включить Unbound, добавьте следующее в /etc/rc.conf:

```
local_unbound_enable="YES"
```

Любые существующие серверы имен в /etc/resolv.conf будут настроены как серверы пересылки в новой конфигурации Unbound.

> **ПРИМЕЧАНИЕ**
>
> Если какой-либо из указанных серверов имен не поддерживает DNSSEC, локальное разрешение DNS завершится ошибкой. Обязательно протестируйте каждый сервер имен и удалите те, которые не прошли тест, например сервер имен, работающий на `192.168.1.1`.

После подтверждения того, что каждый сервер имён поддерживает DNSSEC, запустите Unbound:

```shell
# service local_unbound onestart
```
