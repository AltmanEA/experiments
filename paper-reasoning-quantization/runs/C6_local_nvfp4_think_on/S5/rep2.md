## Deterministic Control Plane

Поток управления Модератора, а также каждая Фаза, Консенсус и решение об Эскалации являются детерминированными функциями от валидированных выходов Роли. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка Сценария возвращается к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте Сессии не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` подача задачи, `2` индивидуальный обзор, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `ожидает оператора`, `решено`, `ошибка`.

| От | К | Условие |
|------|----|-------|
| 1 | 2 | Задача проверена; Сценарий загружен; locked_roles сопоставлены с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствие роли Core |
| 3 | 4 | Достигнут лимит раундов или нет новых `blocked-in-scope` |
| 3 | 3 | Есть хотя бы один `blocked-in-scope` и остаётся бюджет целевого раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: `consensus` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: `no-consensus` при оставшемся бюджете → возврат в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: `blocked-эскалация`; ИЛИ `no-consensus` при исчерпанном бюджете (`no_consensus_budget` достигает нуля → `blocked-эскалация` с `escalation_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный Артефакт сохранён; манифест обновлён в последнюю очередь |
| awaiting-operator | `resume_phase` | Резолюция оператора привязана к `escalation_id` |
| N → N+1 | Обязательно на границах Фаз согласно определению слоя. Быстрый отказ при высоком/критическом Выводе Документатора (перепроверка не пройдена). Недоступность предварительной проверки → разрешение обхода через council.override_precheck (событие precheck.overridden). Обход фиксируется в манифесте как pre_check_override; разрешает ровно один переход, после которого требуется ещё один проход или новый обход. |
| any | failed | Не восстанавливаемое IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; Резолюция поступает через интерфейс оператора. Хук быстрого ревью для обновления `SUBJ-007` зарезервирован, но не реализован на этапе MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсуса. Извлечение с `invalid-format` представляет собой блокирующую ошибку протокола: сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, сформированным структурно конвейером извлечения, исходный отзыв сохраняется, а Роль никогда не учитывается как `Согласие`. Вывод с критическим уровнем, имеющий некорректное обоснование, следует тому же принципу непринятия отказа (согласно `service-contract/error-management/index.md` §Процесс проверки критического Вывода): он понижается до `high` с сохранением исходного текста, а не приводит к полному отклонению отзыва. Отсутствие Роль Core приводит к `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Наличие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз pre_check работает независимо от извлечения Статуса роли, но должен успешно завершиться перед любым продвижением протокола.
