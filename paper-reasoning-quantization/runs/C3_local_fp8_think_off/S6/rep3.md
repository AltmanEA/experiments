## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет результаты по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию произвольного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазам и консенсусу являются детерминированными функциями проверенных выходных данных ролей; ни одна модель не участвует в управлении потоком или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|---------|-------|
| temperature | 0.1 | Задачи аналитического обзора |
| top_p | 0.9 | Задачи аналитического обзора |
| frequency_penalty | 0.0 | нейтральная (явно задача, никогда не выводится) |

Список разрешённых по умолчанию управляется централизованно в файле `defaults/policy.yaml`. Для его расширения требуется создание pull-запроса с обоснованием. Пересмотр осуществляется ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли соответствует известной роли из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Никаких несанкционированных инструкций, добавленных за пределами определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, в котором перечислены точные параметры, использованные для каждой активной роли, с возможностью проследить их до конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты предшествующей фазы), но НЕ изменяет базовый шаблон подсказки роли. Настройка подсказки ограничивается только акцентированием внимания/внедрением контекста — замена поведения запрещена.
