## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через слой 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию произвольного текста, не обладает полномочиями для принятия решений и не содержит вызовов LLM. Решения по фазе и консенсусу являются детерминированными функциями проверенных выводов ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов на основе валидированной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указан вызывающей стороной, либо взят из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии под ключом `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | Значение по умолчанию | Область применения |
|-----------|---------|-------|
| temperature | 0.1 | Задачи обзоров аналитических задач |
| top_p | 0.9 | Задачи обзоров аналитических задач |
| frequency_penalty | 0.0 | нейтральная (явно задача, никогда не выводится) |

Список разрешённых значений по умолчанию управляется централизованно в `defaults/policy.yaml`. Для внесения изменений требуется создание pull request с обоснованием. Пересмотр осуществляется ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- Запрещённые инструкции не добавлены за пределы определения роли и контекста сценария

### Session manifest traceability

Каждая запись сессии включает раздел `"role_agent_config"`, в котором перечислены точные параметры, использованные для каждой активной роли, с возможностью проследить их до конфигурации сценария → резолюции фабрики → фактической инстанции агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (объем задачи, название сценария, результаты предшествующей фазы), но НЕ изменяет базовый шаблон запроса роли. Кастомизация запроса ограничивается только акцентированием внимания/внедрением контекста — подмена поведения запрещена.
