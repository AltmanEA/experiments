## Deterministic Control Plane

Поток управления Модератора, а также каждое решение по фазе, консенсусу и эскалации являются детерминированными функциями проверенных выходов ролей. Ни одна LLM не участвует в управлении потоком или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. Загрузка Сценария переходит к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте Сессии не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` подача задачи, `2` индивидуальное ревью, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `ожидание оператора`, `разрешено`, `не удалось`.

| From | To | Guard |
|------|----|-------|
| 1 | 2 | Задача проверена; Сценарий загружен; locked_roles согласованы с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствующая роль Core |
| 3 | 4 | Достигнут лимит раунда или отсутствует новый `blocked-in-scope` |
| 3 | 3 | Как минимум один `blocked-in-scope` и остаётся целевой бюджет раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: `Консенсус` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: `no-consensus` при оставшемся бюджете → возврат в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: `blocked-Эскалация`; ИЛИ `no-consensus` при исчерпанном бюджете (`no_consensus_budget` достигает нуля → `blocked-Эскалация` с `escalation_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный Артефакт сохранён; манифест обновлён в последнюю очередь |
| awaiting-operator | `resume_phase` | Резолюция оператора привязана к `escalation_id` |
| N → N+1 | Обязательно на границах Фаза согласно определению слоя. Быстрый отказ при высоком/критическом Выводе Документатор (перечек не прошёл). Precheck недоступен → override разрешён через council.override_precheck (precheck.overridden event). Override записывается в манифест как pre_check_override; разрешает ровно один переход, после которого требуется ещё один проход или новый override. |
| any | failed | Не восстанавливаемая ошибка IO или нарушение протокола |

Только `orchestrator/` переводит фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук `SUBJ-007` для быстрого обзора обновления зарезервирован, но не реализован в MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсус. Извлечение в `invalid-format` является блокирующей ошибкой протокола: Сессия переходит в `blocked-Эскалация` с `escalation_reason = information-gap`, сформированным структурно конвейером извлечения, сырой отзыв сохраняется, а Роль никогда не засчитывается как `Согласие`. Критический Вывод с недействительным обоснованием следует тому же принципу непринятия (согласно `service-contract/error-management/index.md` §Процесс проверки критических Выводов): он понижается до `high` с сохранением исходного текста, а не вызывает полное отклонение отзыва. Отсутствующая Роль ядра — это `blocked-Эскалация` с `escalation_reason = risk-threshold-breach`. Проверка наличия Роль ядра выполняется на каждом пути, а не только перед упрощением. Проверка pre_check выполняется независимо от извлечения Статус роли, но должна успешно пройти перед любым продвижением протокола.
