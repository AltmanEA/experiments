## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия:** все манифест-документы, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка контроля:** вызывается при каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Переходы с контролем:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует процесс соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (сетевая ошибка, тайм-аут, сервис недоступен) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор не может быть достигнут (вердикт `недоступен`), MVP Модератора НЕ ДОЛЖЕН блокировать бесконечно. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Переопределение фиксирует `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова переопределения.
- Переопределение допускает ровно один последующий переход в фазу без новой проверки. После этого перехода следующий рубеж требует еще одного прохода или нового переопределения.
- Переопределение никогда не обходит присутствие Core-роли, правила консенсуса или шлюзы целостности эскалации.
