## Deterministic Control Plane

Поток управления Модератора, а также решения по каждой фазе, консенсусу и эскалации являются детерминированными функциями валидированных выходов ролей. Ни одна LLM не участвует в потоке управления или проверке безопасности. Модератор может считывать произвольный текст исключительно для отображения; он никогда не интерпретирует его для принятия решений. При загрузке Сценария происходит возврат к `default-council-session` (см. `scenario/default-council-session.yaml`), если в манифесте сессии не указан явный `scenario_id`.

## Phase State Machine

Состояния: `1` подача задачи, `2` индивидуальный обзор, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `ожидание оператора`, `разрешено`, `провалено`.

| От | До | Ограничение |
|------|----|-------|
| 1 | 2 | Задача проверена; сценарий загружен; locked_roles согласованы с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствие роли Core |
| 3 | 4 | Достигнут лимит раундов или нет новых `blocked-in-scope` |
| 3 | 3 | Как минимум один `blocked-in-scope` и остаётся бюджет целевого раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: `consensus` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: `no-consensus` с оставшимся бюджетом → вход в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: `blocked-escalation`; ИЛИ `no-consensus` с исчерпанным бюджетом (`no_consensus_budget` достигает нуля → `blocked-escalation` с `escalation_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный Артефакт сохранён; manifest обновлён последним |
| awaiting-operator | `resume_phase` | Резолюция оператора привязана к `escalation_id` |
| N → N+1 | Обязательно на границах Фаза согласно определению слоя. Быстрый отказ при высоком/критическом Вывод Документатор (percheck failed). Precheck недоступен → override разрешён через council.override_precheck (precheck.overridden event). Override записан в manifest как pre_check_override; разрешает ровно один переход, после чего требуется ещё один проход или новый override. |
| any | failed | Невосстанавливаемая ошибка IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через поверхность оператора. Хук быстрого обзора для обновления `SUBJ-007` зарезервирован, но не реализован в MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсус. Извлечение с ошибкой `invalid-format` представляет собой блокирующую ошибку протокола: сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, который структурно формируется конвейером извлечения; исходный отзыв сохраняется, а роль никогда не учитывается как `Согласие`. Критический Вывод с недействительным обоснованием подчиняется тому же принципу непринятия отклонений (согласно `service-contract/error-management/index.md` §Critical Вывод Validation Process): он понижается до `high` при сохранении исходного текста, а не приводит к полному отклонению отзыва. Отсутствие Роль Core означает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Присутствие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз `pre_check` функционирует независимо от извлечения Статуса роли, но должен быть успешно пройден перед любым продвижением протокола.
