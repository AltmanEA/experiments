## Deterministic Control Plane

Поток управления Модератора, а также каждое решение относительно Фазы, Консенсуса и Эскалации являются детерминированными функциями от валидированных выходных данных Ролей. Ни одна LLM не участвует в управлении потоком или проверке безопасности. Модератор может читать свободный текст только для отображения; он никогда не интерпретирует его для принятия решений. При загрузке Сценария, если в манифесте Сессии не указан явный `scenario_id`, используется значение по умолчанию `default-council-session` (см. `scenario/default-council-session.yaml`).

## Phase State Machine

Состояния: `1` отправка задачи, `2` индивидуальное ревью, `3` обсуждение, `4` проверка консенсуса, `5` резолюция, плюс `awaiting-operator`, `resolved`, `failed`.

| Откуда | Куда | Условие |
|------|----|-------|
| 1 | 2 | Задача проверена; сценарий загружен; locked_roles согласованы с operator_approval согласно `service-contract/index.md` §Сессия Manifest |
| 2 | 3 | Каждая активная роль имеет `RoleStatus` с `extraction = parsed` |
| 2 | awaiting-operator | Любой статус `invalid-format` или отсутствующая роль Core |
| 3 | 4 | Достигнут лимит раунда или нет нового `blocked-in-scope` |
| 3 | 3 | Существует хотя бы один `blocked-in-scope` и остается бюджет целевого раунда |
| 4 | 5 | Согласно таблице protocol-core §Outcome-to-Transition: `консенсус` или `conditional` → Фаза 5 |
| 4 | 3 | Согласно таблице protocol-core §Outcome-to-Transition: `no-консенсус` с оставшимся бюджетом → повторный вход в Фаза 3; уменьшает `no_consensus_budget`. |
| 4 | awaiting-operator | Согласно таблице protocol-core §Outcome-to-Transition: `blocked-эскалация`; ИЛИ `no-консенсус` с исчерпанным бюджетом (`no_consensus_budget` достигает нуля → `blocked-эскалация` с `эскалация_reason = information-gap`) → `awaiting-operator` |
| 5 | resolved | Финальный артефакт сохранен; manifest обновлен последним |
| awaiting-operator | `resume_phase` | Резолюция оператора связана с `escalation_id` |
| N → N+1 | Обязательно на границах фаз согласно определению слоя. Быстрый отказ при высоком/критическом Выводе Документатора (percheck failed). Precheck недоступен → переопределение разрешено через council.override_precheck (precheck.overridden event). Переопределение записано в manifest как pre_check_override; разрешает ровно один переход, после которого требуется еще один проход или новое переопределение. |
| any | failed | Невосстановимая ошибка IO или нарушение протокола |

Только `orchestrator/` продвигает фазу. Оператор никогда не редактирует состояние фазы напрямую; резолюция поступает через интерфейс оператора. Хук обновления для быстрого обзора `SUBJ-007` зарезервирован, но не реализован на этапе MVP.

## Role Status Handling

`extract_role_status()` является единственным источником истины для Консенсуса. Извлечение с `invalid-format` представляет собой блокирующую ошибку протокола: сессия переходит в `blocked-escalation` с `escalation_reason = information-gap`, структурно сгенерированным конвейером извлечения, исходный обзор сохраняется, а Роль никогда не учитывается как `Согласие`. Критический Вывод с некорректным обоснованием следует тому же принципу непринятия отклонения (согласно `service-contract/error-management/index.md` §Процесс валидации Вывода): он понижается до `high` с сохранением исходного текста, вместо того чтобы вызывать полное отклонение обзора. Отсутствие Роль Core означает `blocked-escalation` с `escalation_reason = risk-threshold-breach`. Присутствие Роль Core проверяется на каждом пути, а не только перед упрощением. Шлюз `pre_check` работает независимо от извлечения Статуса роли, но должен успешно пройти перед любым продвижением протокола.
