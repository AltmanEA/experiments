## Moderator

Модератор — это детерминированная управляющая плоскость внутри `orchestrator/`. Он агрегирует статусы ролей, объединяет выводы по `subject_id`, оценивает консенсус через Layer 0 и маршрутизирует эскалацию. Он не выполняет интерпретацию произвольного текста, не наделён полномочиями для принятия решений и не содержит вызовов LLM. Решения по Фазе и консенсусу являются детерминированными функциями валидированных выходов ролей; ни одна модель не участвует в управляющем потоке или проверке безопасности.

## RoleAgentFactory

Централизованная фабрика, создающая экземпляры ролевых агентов из проверенной конфигурации сценария.

### Zero silent defaults policy (ADR-002)

Каждый параметр либо указывается вызывающей стороной, либо берётся из задокументированного безопасного замечания, видимого в манифесте сессии. Никаких магических значений по умолчанию. Все применённые замечания по умолчанию отображаются в записи сессии в поле `"configuration_source": "scenario_defaults"` или `"configuration_source": "operator_explicit"`.

| Параметр | По умолчанию | Область применения |
|-----------|---------|-------|
| temperature | 0.1 | аналитическая-задача обзоры |
| top_p | 0.9 | аналитическая-задача обзоры |
| frequency_penalty | 0.0 | нейтральный (задан явно, никогда не выводится) |

Белый список по умолчанию управляется централизованно в `defaults/policy.yaml`. Расширение требует PR с обоснованием. Рассматривается ежеквартально.

### Contract validation hook

После создания, но перед добавлением в очередь, проверьте:

- Идентификатор роли совпадает с известной ролью из `protocol-core/index.md`
- Шаблон запроса содержит необходимые разделы (перспектива, обязанности, напоминание о структуре вывода)
- За пределами определения роли и контекста сценария не добавлено несанкционированных инструкций

### Session manifest traceability

Каждая запись сессии включает раздел "Роль_agent_config", перечисляющий точные параметры, использованные для каждой активной роли, с возможностью проследить до конфигурации сценария → резолюции фабрики → фактического инстанциирования агента.

### No prompt modification rule

Фабрика внедряет контекст, специфичный для сценария (область задачи, название сценария, результаты перед фазой), но НЕ изменяет базовый шаблон запроса роли. Настройка запроса ограничена исключительно введением акцентов/контекста — поведенческая подмена запрещена.
