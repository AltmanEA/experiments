## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации перед фиксацией переходов состояния протокола. Он выполняется на уровне 2 (операторской поверхности) как синхронный вызов `audit(pre_check=true)` в Документаторе и возвращает вердикт вызывающей стороне в рамках того же самого вызова.

- **Целевая область:** все манифест-документы, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка принудительного применения:** вызывается при каждом переходе границы фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Переходы с контролем:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсус), `4 → 5` (резолюция). Переход разрешен только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; рантайм считывает это поле/событие при следующей оценке границы и либо продолжает, либо блокирует соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, недоступность сервиса) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. режим Override ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed per C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (`unavailable` вердикт), Модератор MVP НЕ ДОЛЖЕН блокировать бесконечно. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен, несмотря на сбой:

- Отмена фиксирует `reason` (свободный текст, объясняющий, почему барьер был обойден).
- Отмена записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` синхронно генерируется при вызове отмены.
- Отмена разрешает ровно один последующий переход Фаза без нового аудита. После этого перехода следующая граница требует еще один проход или новую отмену.
- Отмена никогда не обходит присутствие Core-Роль, правила Консенсус или барьеры целостности Эскалация.
