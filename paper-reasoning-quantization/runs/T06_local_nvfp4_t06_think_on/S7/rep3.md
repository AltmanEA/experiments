## `pre_check` Gate

### Scope and Enforcement Point

Шлюз `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояний протокола. Он выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же самого вызова.

- **Целевой охват:** все манифест-документы, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка применения:** срабатывает на каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед сохранением нового состояния фазы в Layer 1.
- **Переходы с проверкой:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешён только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` при переопределении или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей оценке границы и либо продолжает работу, либо блокирует процесс соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевой области | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Блокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (сбой сети, тайм-аут, недоступность сервиса) | `unavailable` | Блокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудита Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Блокировать переход (fail-closed per C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (вердикт `unavailable`), MVP модератора не должен бесконечно блокироваться. Аутентифицированный `council.override_precheck(reason, operator_id)` может продолжить выполнение, несмотря на сбой:

- Переопределение фиксирует `reason` (свободный текст, объясняющий, почему шлюз был обойден).
- Переопределение записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова переопределения.
- Переопределение допускает ровно один последующий переход Фаза без новой проверки. После этого перехода следующий рубеж требует еще одного прохода или нового переопределения.
- Переопределение никогда не обходит присутствие Core-Роль, правила Консенсуса или шлюзы целостности Эскалации.
