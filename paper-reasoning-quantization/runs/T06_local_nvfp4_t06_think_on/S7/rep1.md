## `pre_check` Gate

### Scope and Enforcement Point

Контрольная точка `pre_check` представляет собой проверку целостности артефактов документации до фиксации переходов состояния протокола. Она выполняется на уровне 2 (поверхность оператора) в виде синхронного вызова к `audit(pre_check=true)` Документатора и возвращает вердикт вызывающей стороне в рамках того же вызова.

- **Область действия:** все документы манифеста, относящиеся к текущей сессии (определяемые по `target_id` из активного сценария).
- **Точка применения:** вызывается при каждом переходе через границу фазы (`2 → 3`, `3 → 4`, `4 → 5`) перед фиксацией нового состояния фазы в Layer 1.
- **Контролируемые переходы:** `2 → 3` (начало обсуждения), `3 → 4` (проверка консенсуса), `4 → 5` (резолюция). Переход разрешен только при вердикте `pass`.
- **Передача вердикта в Layer 1:** поверхность записывает результат вердикта (pass/fail/reason) в поле манифеста `pre_check_override` в случае переопределения или генерирует событие `precheck.failed`; среда выполнения считывает это поле/событие при следующей проверке границы и либо продолжает выполнение, либо блокирует его соответственно.

### Verdict Logic

| Условие | Вердикт | Действие |
|-----------|---------|--------|
| Нет `high`/`critical` выводов для целевого диапазона | `pass` | Продолжить переход |
| Присутствует любой `high` или `critical` вывод | `fail` | Заблокировать переход; сгенерировать событие `precheck.failed` |
| Документатор недоступен (ошибка сети, тайм-аут, недоступность сервиса) | `unavailable` | Заблокировать переход; сгенерировать событие `precheck.unavailable` (см. режим переопределения ниже) |
| Реестр аудитов Документатора отсутствует/поврежден/недоступен для чтения | `fail` | Заблокировать переход (fail-closed согласно C-03) |

### Documenter Unavailable — Override Mode

Когда Документатор недоступен (`unavailable` вердикт), MVP модератора НЕ ДОЛЖЕН бесконечно блокироваться. Аутентифицированный `council.override_precheck(reason, operator_id)` может быть выполнен несмотря на сбой:

- Обход фиксирует `причину` (свободный текст, объясняющий, почему шлюз был обойден).
- Обход записывается в манифест через поле `pre_check_override`.
- Событие `precheck.overridden` генерируется синхронно во время вызова обхода.
- Обход допускает ровно один последующий переход Фаза без нового аудита. После этого перехода следующая граница требует повторного прохода или нового обхода.
- Обход никогда не обходит присутствие Core-Роль, правила Консенсус или шлюзы целостности Эскалация.
